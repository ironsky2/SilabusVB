Chunking: Memecah Pekerjaan

Fondasi & Cara Kerja 90 menit

Tujuan: Peserta bisa mengubah PRD menjadi antrean tugas kecil yang bisa dikerjakan satu per satu.

📚 Teori

  • Kenapa instruksi "buatkan seluruh aplikasi" hampir selalu gagal total
  • Urutan chunking: Halaman → Komponen → State / Logika → Styling
  • Satu sesi AI = satu tugas jelas dengan kriteria selesai yang bisa diuji

🧑‍💻 Praktikum — Prompt AI

💡 Salin prompt ini lalu paste ke Antigravity AI / AI Assistant kamu.

🤖 PROMPT KE AI ASSISTANT Pertemuan 4

3. Urutkan dari paling dasar ke paling kompleks

Modul 5: Git Sebelum Coding — Jaring Pengaman Wajib Vibe Coder

Bangun Halaman Pertama 90 menit Modul Praktikum Lengkap

Tujuan: Peserta memahami mengapa Git adalah keharusan sebelum mengizinkan AI menyentuh kode, punya jaring pengaman, dan menguasai alur kerja commit hingga pemulihan kode yang dirusak AI.

📚 Teori

  • Git = Mesin Waktu Proyek: Analogi foto snapshot di kamera polaroid sebelum merenovasi ruangan
  • Bahaya Tanpa Git: AI tidak punya tombol "undo" — satu prompt yang salah bisa merusak file tanpa titik kembali
  • Kamus 5 Istilah Git: Repository (gudang), Commit (snapshot simpan), Staging (pilih file foto), Branch (cabang), Checkout (kembali ke aman)
  • Aturan Emas Vibe Coder: "Commit sebelum minta AI melakukan perubahan besar" — jadikan ini refleks wajib
  • Siklus Kerja Aman: Mulai sesi → Kerjakan fitur kecil → 📸 COMMIT → Minta AI bantu → Cek hasil di browser

🧑‍💻 Praktikum — 5 Prompt AI

💡 Buka halaman modul praktikum lengkap untuk menyalin 5 prompt siap pakai ini.

  • Prompt 1 (P5.1): Inisialisasi repo Git, buat .gitignore aman, README.md, dan commit pertama
  • Prompt 2 (P5.2): Kuasai siklus harian git status, git diff, git add, dan commit message profesional
  • Prompt 3 (P5.3) ⭐: Simulasi AI rusak kode & pemulihan darurat dalam 5 detik (git checkout, git restore)
  • Prompt 4 (P5.4): Strategi Atomic Commit, 5 trigger wajib commit, dan checklist video game save point
  • Prompt 5 (P5.5): Membaca riwayat git log --oneline, inspeksi perubahan AI, dan audit trail

Modul 6: Push Project ke GitHub — Backup, Portofolio & Kolaborasi Cloud

Bangun Halaman Pertama 90 menit Modul Praktikum Cloud

Tujuan: Proyek lokal terhubung dan terunggah aman ke GitHub Cloud — memiliki standar pesan Conventional Commits, etalase README.md profesional, branch main terstandar, dan mampu sinkronisasi pull & perbaikan error push.

📚 Teori

  • GitHub Cloud: Mengapa repo di laptop bukan cadangan aman jika laptop rusak/hilang — cloud adalah etalase portofolio publik
  • Conventional Commits: Standar format pesan commit profesional (feat:, fix:, docs:, refactor:, style:)
  • README.md Standard: Elevator pitch, daftar fitur berikon, tech stack, dan instruksi instalasi lokal
  • Remote Origin & Upstream: Mendaftarkan URL GitHub (git remote add origin) dan mengunci pelacakan upstream (-u)
  • Alur Sinkronisasi Cloud: First Push, Daily Push 1-Langkah, git pull, serta resolusi merge conflict

🧑‍💻 Praktikum — 7 Modul Cloud Push

💡 Buka halaman modul praktikum lengkap untuk menyalin prompt siap pakai ini.

  • Standar Wajib: Pembuatan pesan commit berformat Conventional Commits
  • Prompt 1 (P6.1): Generator file README.md portofolio profesional via AI
  • Prompt 2 (P6.2): Hubungkan repo lokal ke remote origin & set branch main
  • Prompt 3 (P6.3): First push unggah perdana (git push -u origin main)
  • Prompt 4 (P6.4): Alur push rutin harian 1-langkah (Stage → Commit → Push)
  • Prompt 5 (P6.5): Sinkronisasi pembaruan & resolusi Merge Conflict (git pull)
  • Prompt 6 (P6.6): Dokter error push (diagnosis otomatis: rejected non-fast-forward, rebase, token)

Menyambung ke Layanan Luar (API & Cloud Client)

Interaktif & Data 120 menit

Tujuan: Aplikasi bisa berkomunikasi dengan backend cloud secara aman tanpa membocorkan kredensial.

📚 Teori

  • Bagaimana aplikasi "berbicara" dengan server di internet (konsep API)

  • Pentingnya menangani kondisi gagal: lambat, offline, atau data kosong

Konsep #1 — Database

Supabase & PostgreSQL: Gudang Data Milikmu

🏪
Analogi: Bayangkan Sebuah Minimarket

Database itu seperti gudang minimarket. Setiap jenis produk disimpan di rak yang berbedasnack di rak A, minuman di rak B, produk kebersihan di rak C. Dalam database, "rak" ini disebut tabel. Setiap baris di rak adalah satu baris data (record). Dan setiap kolom label harga, nama produk, stok itulah kolom (field).

Supabase adalah layanan cloud yang menyediakan gudang (PostgreSQL) sekaligus kasir otomatis (API)sehingga kamu tidak perlu membangun gudang dari awal.

1
Tabel = Rak Gudang

Kita punya 3 tabel utama: profiles (data pengguna), categories (kategori transaksi), dan transactions (catatan uang masuk/keluar).

2
Foreign Key = Rak Terhubung

Setiap transaksi milik seorang user dan masuk dalam satu kategori. Foreign Key adalah cara memberi tahu database bahwa "rak ini terhubung ke rak itu".

3
Trigger = Satpam Otomatis

Saat user baru daftar, secara otomatis database akan membuat profil kosong untuknya. Ini dilakukan oleh Trigger — seperti satpam yang langsung memberi kartu anggota begitu tamu masuk.

4
Index = Katalog Pencarian

Tanpa index, database harus memeriksa setiap baris satu per satu (seperti cari produk tanpa katalog). Index adalah daftar isi yang membuat pencarian 10–100× lebih cepat.

💡 Insight Utama

PostgreSQL (mesin di balik Supabase) adalah salah satu database paling andal di dunia. Dipakai oleh perusahaan seperti Instagram, Spotify, dan GitHub. Dengan Supabase, kamu mendapat kekuatan enterprise-grade tanpa harus menjadi ahli server.

🔐
Konsep #2 — Row Level Security (RLS)

RLS: Gembok Per-Baris Data

🏦
Analogi: Brankas Bank

Bayangkan sebuah bank. Semua uang nasabah ada di satu brankas besar (database yang sama). Namun setiap nasabah hanya bisa mengambil uangnya sendiribukan milik orang lain. Itulah cara kerja Row Level Security (RLS).

Tanpa RLS, jika ada bug di aplikasi atau seseorang yang iseng memanggil API secara langsung, mereka bisa membaca data semua user sekaligus. Sangat berbahaya! RLS adalah lapisan keamanan di level databasebahkan jika aplikasimu punya bug, data tetap aman.

🔴 Tanpa RLS — Data Bocor!

Query sederhana:

SELECT * FROM transactions

PostgreSQL langsung mengembalikan semua baris dari semua pengguna tanpa filter. User A bisa melihat data User B!

⚠️ 1.000 transaksi dari 500 user dikembalikan semua
🟢 Dengan RLS — Aman!

Query yang sama:

SELECT * FROM transactions

PostgreSQL secara otomatis menambahkan filter tersembunyi: WHERE user_id = auth.uid(). User A hanya melihat datanya sendiri.

✅ Hanya 2 transaksi milik user yang login dikembalikan
🔑 3 Jenis Policy RLS yang Wajib Dipahami
SELECT Policy BACASiapa yang boleh melihat data? Jawaban: "Hanya pemilik data."
INSERT Policy TULIS — Siapa yang boleh menambah data? Jawaban: "User yang login, dan hanya dengan user_id miliknya sendiri."
UPDATE / DELETE Policy UBAH/HAPUSHanya pemilik data yang boleh mengubah atau menghapus datanya sendiri.
⚠️ Peringatan Penting

Jangan pernah mematikan RLS di production! Anggap RLS seperti helm saat berkendara memang sedikit merepotkan saat setup, tapi tanpanya satu kecelakaan kecil bisa berakibat fatal. Semua tabel yang menyimpan data user WAJIB mengaktifkan RLS.

Konsep #3 — Authentication (Auth)

Auth: Sistem Masuk & Identitas Pengguna

Konsep #4 — Realtime Subscription

PROMPT KE ANTIGRAVITY AGENT

[INSTRUCTION]:

-- 1. FUNCTION: Auto-update timestamp saat row dimodifikasi
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 2. TABEL PROFILES (relasi 1-to-1 dengan auth.users)
CREATE TABLE IF NOT EXISTS public.profiles (
  id          UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY,
  full_name   TEXT,
  avatar_url  TEXT,
  updated_at  TIMESTAMPTZ DEFAULT now()
);

CREATE OR REPLACE TRIGGER profiles_updated_at
  BEFORE UPDATE ON public.profiles
  FOR EACH ROW EXECUTE FUNCTION update_updated_at_column();

-- 3. TABEL CATEGORIES (per user)
CREATE TABLE IF NOT EXISTS public.categories (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  color       TEXT DEFAULT '#028090',
  icon        TEXT DEFAULT 'tag',
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 4. TABEL TRANSACTIONS (catatan keuangan)
CREATE TABLE IF NOT EXISTS public.transactions (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  category_id UUID REFERENCES public.categories(id) ON DELETE SET NULL,
  title       TEXT NOT NULL,
  amount      NUMERIC(15,2) NOT NULL,
  type        TEXT NOT NULL CHECK (type IN ('income', 'expense')),
  note        TEXT,
  date        DATE DEFAULT CURRENT_DATE,
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 5. FUNCTION + TRIGGER: Auto-buat profile saat user baru terdaftar
CREATE OR REPLACE FUNCTION handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.profiles (id, full_name, avatar_url)
  VALUES (
    NEW.id,
    NEW.raw_user_meta_data ->> 'full_name',
    NEW.raw_user_meta_data ->> 'avatar_url'
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE OR REPLACE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION handle_new_user();

-- 6. INDEX PERFORMA
CREATE INDEX IF NOT EXISTS idx_transactions_user_id ON public.transactions(user_id);
CREATE INDEX IF NOT EXISTS idx_transactions_date     ON public.transactions(date DESC);
CREATE INDEX IF NOT EXISTS idx_categories_user_id    ON public.categories(user_id);

-- 1. PROFILES POLICIES
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;

CREATE POLICY "profiles: select own"

CREATE POLICY "profiles: update own"

import { createContext, useContext, useEffect, useState, useCallback } from 'react';
import type { ReactNode } from 'react';
import type { Session, User, AuthError } from '@supabase/supabase-js';
import { supabase } from '../lib/supabase';
import type { Profile } from '../types/database.types';

interface AuthContextType {
  user: User | null;
  session: Session | null;
  profile: Profile | null;
  loading: boolean;
  signUpWithEmail: (e: string, p: string, name: string) => Promise<{ error: AuthError | null }>;
  signInWithEmail: (e: string, p: string) => Promise<{ error: AuthError | null }>;
  signOut: () => Promise<void>;
}

const AuthContext = createContext<AuthContextType | undefined>(undefined);

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const [session, setSession] = useState<Session | null>(null);
  const [profile, setProfile] = useState<Profile | null>(null);
  const [loading, setLoading] = useState<boolean>(true);

  const fetchProfile = useCallback(async (userId: string) => {
    const { data } = await supabase.from('profiles').select('*').eq('id', userId).single();
    setProfile(data);
  }, []);

  useEffect(() => {
    supabase.auth.getSession().then(({ data: { session } }) => {
      setSession(session);
      setUser(session?.user ?? null);
      if (session?.user) fetchProfile(session.user.id);
      setLoading(false);
    });

    const { data: { subscription } } = supabase.auth.onAuthStateChange((_evt, session) => {
      setSession(session);
      setUser(session?.user ?? null);
      if (session?.user) fetchProfile(session.user.id);
      else setProfile(null);
      setLoading(false);
    });

    return () => subscription.unsubscribe(); // Safe Cleanup
  }, [fetchProfile]);

  const signUpWithEmail = async (email: string, password: string, fullName: string) => {
    const { error } = await supabase.auth.signUp({
      email, password, options: { data: { full_name: fullName } }
    });
    return { error };
  };

  const signInWithEmail = async (email: string, password: string) => {
    const { error } = await supabase.auth.signInWithPassword({ email, password });
    return { error };
  };

  const signOut = async () => { await supabase.auth.signOut(); };

  return (
    <AuthContext.Provider value={{ user, session, profile, loading, signUpWithEmail, signInWithEmail, signOut }}>
      {children}
    </AuthContext.Provider>
  );
}

export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) throw new Error('useAuth harus digunakan di dalam <AuthProvider>');
  return context;
}

Realtime Subscription Hook dengan Safe Cleanup

supabase.channel() · Auto Reconnect · Memory Leak Prevention · Optimistic Update

Custom Hook useTransactions yang otomatis menyinkronkan data antar-perangkat secara realtime dan membersihkan koneksi WebSocket saat komponen di-unmount:

PROMPT 5 KE ANTIGRAVITY AGENT: BUAT REALTIME SYNC HOOK 
[ROLE]: Senior Frontend Engineer (Realtime Systems)
[CONTEXT]: Supabase Client di `src/lib/supabase.ts` dan user login dari `useAuth()`.
[TASK]:
Buatkan custom hook `src/hooks/useTransactions.ts`:
1. Fetch data transaksi awal terurut berdasarkan tanggal terbaru untuk user yang sedang login (`user_id = user.id`).
2. Buat Realtime WebSocket Channel `supabase.channel('transactions_' + user.id)`:
   - Dengarkan event `postgres_changes` untuk tabel `transactions` dengan filter `user_id=eq.${user.id}`.
   - Otomatis sinkronkan state transaksi setiap kali ada penambahan, perubahan, atau penghapusan data.
3. Wajib tambahkan fungsi pembersihan (`supabase.removeChannel(channel)`) pada return `useEffect` agar tidak terjadi memory leak.
4. Sediakan helper method `addTransaction(data)` dan `deleteTransaction(id)` dengan optimistic UI update.
FILE: src/hooks/useTransactions.ts 
import { useState, useEffect, useCallback } from 'react';
import { supabase } from '../lib/supabase';
import { useAuth } from '../context/AuthContext';
import type { Transaction, TransactionInsert } from '../types/database.types';

export function useTransactions() {
  const { user } = useAuth();
  const [transactions, setTransactions] = useState<Transaction[]>([]);
  const [isLoading, setIsLoading] = useState<boolean>(true);

  const fetchTransactions = useCallback(async () => {
    if (!user) { setTransactions([]); setIsLoading(false); return; }
    setIsLoading(true);
    const { data } = await supabase
      .from('transactions')
      .select('*, categories(*)')
      .eq('user_id', user.id)
      .order('date', { ascending: false });
    setTransactions((data as Transaction[]) ?? []);
    setIsLoading(false);
  }, [user]);

  useEffect(() => {
    fetchTransactions();
    if (!user) return;

    // Realtime channel filter user_id
    const channel = supabase
      .channel(`transactions_${user.id}`)
      .on(
        'postgres_changes',
        { event: '*', schema: 'public', table: 'transactions', filter: `user_id=eq.${user.id}` },
        () => { fetchTransactions(); }
      )
      .subscribe();

    // Cleanup: cegah memory leak saat unmount
    return () => { supabase.removeChannel(channel); };
  }, [user, fetchTransactions]);

  const addTransaction = async (data: TransactionInsert) => {
    if (!user) return { error: 'Belum login' };
    const { error } = await supabase.from('transactions').insert({ ...data, user_id: user.id });
    return { error: error?.message ?? null };
  };

  const deleteTransaction = async (id: string) => {
    // Optimistic delete UI
    const prev = [...transactions];
    setTransactions(t => t.filter(x => x.id !== id));
    const { error } = await supabase.from('transactions').delete().eq('id', id);
    if (error) setTransactions(prev); // rollback jika gagal
    return { error: error?.message ?? null };
  };

  return { transactions, isLoading, addTransaction, deleteTransaction, refetch: fetchTransactions };
}
