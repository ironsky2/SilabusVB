01
Praktikum Modul 1

Persiapan Workspace Antigravity & Konfigurasi Rules Proyek

Waktu: 45 Menit Planning Mode
1

Buka Workspace di Antigravity IDE & Inisialisasi Git

Buka folder proyek Anda di Antigravity IDE. Pastikan repositori git sudah diinisialisasi melalui terminal terintegrasi Antigravity.

git init -b main
2

Tanamkan Konfigurasi AI Rules (`GEMINI.md` / System Prompt Antigravity)

Buat file konfigurasi peraturan agar agent Antigravity selalu menghasilkan kode lengkap (*No Lazy Code*) dan type-safe.

File: GEMINI.md (atau .gemini/rules) 
# Antigravity AI Pair Programming Rules
- Stack: Vite + React 18 (TypeScript) + Tailwind CSS + vite-plugin-pwa + @supabase/supabase-js
- Architecture: Architect First, Code Second. Always plan before modifying files.
- Coding Standards: Strict TypeScript (no 'any'). Full code only (never use '// implement here' placeholder).
- Security: Never expose SUPABASE_SERVICE_ROLE_KEY to frontend. Always enforce Row Level Security (RLS).
- PWA: Mobile-first responsive UI with notch safe-area support and offline caching.
3

Uji Planning Mode dengan Slash Command Antigravity

Ketik perintah di chat Antigravity untuk menyelaraskan desain arsitektur sebelum membuat file:

Prompt ke Agent Antigravity:
/grill-me "Saya ingin membangun aplikasi PWA Smart Finance terhubung Supabase. Wawancarai saya terkait kebutuhan database, user flow, dan fitur PWA yang wajib ada sebelum membuat implementation_plan.md."
Checkpoint Kelulusan Lab 1:

File `GEMINI.md` tersimpan di root workspace, repositori git aktif, dan Antigravity mengerti aturan proyek.

Praktikum Modul 2

Scaffolding PWA, Manifest & Mobile Shell dengan Antigravity

Waktu: 60 Menit PWA Workbox
1

Minta Antigravity Scaffold Proyek Vite + Tailwind

Kirim task prompt pertama ke agent Antigravity untuk menjalankan pembuatan file dasar:

// Prompt di Chat Antigravity:
"Tolong scaffold proyek React 18 TypeScript dengan Vite, Tailwind CSS, dan Lucide React icons. Pastikan konfigurasi Tailwind memiliki plugin container dan safe-area support. Jalankan perintah instalasi dependency."
2

Instalasi & Konfigurasi `vite-plugin-pwa`

Minta Antigravity mengonfigurasi service worker Workbox dan Web App Manifest:

Prompt PWA ke Antigravity
Gunakan Task Prompt Modul 2 pada tab "Template Prompt" di bawah untuk menghasilkan `vite.config.ts` dan `src/components/InstallPrompt.tsx`.
3

Implementasi Mobile Safe Area di `index.html` & CSS

Pastikan Antigravity menambahkan meta tag `viewport-fit=cover` dan kelas padding notch pada layout utama:

<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
4

Verifikasi di Antigravity Browser Preview / DevTools

Buka preview aplikasi di Antigravity IDE atau browser Chrome. Buka DevTools → Application → Manifest dan verifikasi bahwa nama, icons, dan display `standalone` terdeteksi dengan benar.

Checkpoint Kelulusan Lab 2:

Service worker terdaftar (*Status: activated and running*), banner install muncul di desktop/mobile, dan lakukan Git Commit: `git commit -m "feat: setup pwa and mobile shell"`.

03
Praktikum Modul 3

Integrasi Supabase: Database Schema, RLS, Auth & Realtime Hooks

Waktu: 90 Menit Row Level Security
1

Minta Antigravity Menulis Skema SQL & RLS Policies

Gunakan prompt khusus database Supabase untuk menghasilkan script SQL DDL lengkap dengan trigger dan policy keamanan:

Kirim Task Prompt Database (Modul 3) → Salin hasil SQL ke Supabase Dashboard → SQL Editor → Run.
2

Setup `.env.local` & Supabase Client Singleton

Buat file environment di Antigravity IDE (pastikan masuk ke `.gitignore`):

VITE_SUPABASE_URL=https://xyzcompany.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Minta Antigravity membuat file client singleton di `src/lib/supabase.ts` dan tipe data di `src/types/database.types.ts`.

3

Buat AuthContext, Custom Hook `useAuth`, & Route Guard

Minta Antigravity membuat `src/context/AuthContext.tsx` dan `src/components/ProtectedRoute.tsx`. Uji alur Sign Up, Login, dan Logout pada browser preview.

4

Buat Realtime Subscription Hook dengan Safe Cleanup

Minta Antigravity membuat custom hook data (misal `src/hooks/useTransactions.ts`) yang otomatis men-subscribe perubahan realtime via `supabase.channel()` dan membersihkan channel saat komponen unmount.

Checkpoint Kelulusan Lab 3:

User dapat register/login, data CRUD tersimpan di PostgreSQL dengan proteksi RLS (user A tidak bisa melihat data user B), dan data sync realtime tanpa refresh browser.

04
Praktikum Modul 4

Debugging Sistematis & Surgical Refactoring di Antigravity

Waktu: 60 Menit Subagents & Diff
1

Simulasi Error & Protokol Feedback Loop 3-Pilar

Saat terjadi compiler error atau runtime bug, jangan menulis prompt umum. Kirimkan pesan terstruktur:

// Format Feed ke Antigravity:
1. [Raw Error]: TS2339: Property 'user_id' does not exist on type 'Transaction'
2. [File]: src/hooks/useTransactions.ts baris 35-50
3. [Expected]: Filter transaksi berdasarkan user.id yang sedang aktif.
2

Surgical Refactoring File Monolitik via Antigravity Planning Mode

Jika sebuah komponen melebihi 250 baris kode, mintalah Antigravity membuat rencana pemecahan (*implementation plan*) menjadi:

  • Custom Logic Hook di `src/hooks/`
  • Pure UI Subcomponents di `src/components/[Feature]/`
  • Main Orchestrator Component (< 80 baris)
3

Delegasi Deep Research ke Subagent Antigravity

Gunakan subagent `research` Antigravity untuk menyelidiki skenario rumit seperti Workbox background sync atau offline cache invalidation tanpa mengotori chat utama.

Checkpoint Kelulusan Lab 4:

Tidak ada file komponen monolitik >250 baris, zero TypeScript errors di terminal Antigravity, dan kode berjalan mulus saat offline mode diaktifkan di DevTools.

Cheat Sheet: 7 Aturan Emas Vibe Coding

Prinsip fundamental agar AI tidak berhalusinasi, tidak memotong kode, dan menjaga integritas arsitektur.

Standar Disiplin Siswa
01 Modular Scope

One Prompt, One File / One Task

Fokuskan setiap permintaan pada 1 file atau 1 fungsi spesifik. Jangan meminta frontend, database, auth, dan grafik sekaligus dalam 1 prompt karena memicu pemotongan kode dan halusinasi.

"Buatkan app finance lengkap dg DB & chart"
"Buat skema SQL tabel 'transactions' saja"
02 Context Anchor

Bawa Konteks, Jangan Berasumsi

AI tidak menyimpan memori antar chat tanpa konteks eksplisit. Pasang selalu anchor tech stack, path file yang sedang dikerjakan, dan interfaces yang sudah ada pada awal prompt.

Context: Vite + React TS + Tailwind. File: src/lib/supabase.ts
03 No Lazy Code

Prinsip "No Lazy Code" (Anti Placeholder)

Tolak kode dengan komentar malas seperti // rest of code atau /* implement here */. Instruksikan secara tegas untuk menulis kode utuh.

"Tulis seluruh file/komponen secara utuh tanpa komentar placeholder atau pemotongan."
04 Dependency Guard

Kunci Stack & Dependensi

Cegah AI menambahkan package baru secara sembarangan (misal mengganti `lucide-react` ke `react-icons` atau menginstal `axios` padahal proyek memakai `@supabase/supabase-js`).

"Hanya gunakan library yang sudah ada: lucide-react, tailwindcss, @supabase/supabase-js."
05 Debug Protocol

Protokol Debugging 3-Pilar

Jangan hanya menulis "Kodenya error!". Kirimkan 3 informasi wajib: (1) Raw error dari Terminal/DevTools, (2) File sumber masalah, dan (3) Ekspektasi hasil yang diinginkan.

Feed: [Raw Error] + [Code Snippet] + [Expected Behavior]
06 Type Contract

Validasi Schema & Types Sebelum UI

Kunci interface TypeScript (`database.types.ts`) terlebih dahulu. Memulai dari UI tanpa kontrak tipe data memaksa AI mengarang (*hallucinate*) properti database yang tidak pernah ada.

SQL DDL → Database Types → React Component
07

Git Atomic Commit Setiap Kali Satu Prompt Berhasil

Jangan pernah melanjutkan prompt berikutnya sebelum kode dari prompt sebelumnya diuji dan berfungsi. Jalankan git commit untuk setiap iterasi kecil agar Anda bisa langsung rollback jika prompt berikutnya merusak sistem.

git add . && git commit -m "feat: setup supabase auth"

Koleksi Template Prompt Siap Pakai (R-C-I-C)

Salin prompt teruji ini langsung ke AI Assistant (Antigravity / Cursor / ChatGPT / Claude).

System Rules

Master Instruction / GEMINI.md

Anda adalah Senior Fullstack Engineer & PWA Specialist di Google Antigravity IDE. Anda bertindak sebagai AI Pair Programmer dengan standar kode industri, performa tinggi, dan keamanan ketat.

Tech Stack Proyek:
- Framework: Vite + React 18 (TypeScript)
- Styling: Tailwind CSS & Lucide React icons
- PWA Engine: vite-plugin-pwa (Workbox StaleWhileRevalidate strategy)
- Backend & Auth: Supabase (@supabase/supabase-js) + PostgreSQL with Row Level Security (RLS)

Aturan Kerja Wajib:
1. ARCHITECT FIRST: Kerjakan satu task / satu file dalam satu waktu. Jangan melompat ke UI sebelum data types dan schema database disepakati.
2. NO LAZY CODE: Tulis kode secara utuh dan lengkap. Dilarang menggunakan placeholder seperti "// implement logic here" atau "// rest of code".
3. STRICT TYPES: Wajib gunakan TypeScript interfaces/types yang ketat. Hindari tipe data 'any'.
4. STACK INTEGRITY: Dilarang mengganti atau menambah library eksternal tanpa instruksi eksplisit.
5. PWA COMPLIANCE: Pastikan setiap UI mobile-friendly, mendukung safe-area notch iOS/Android, dan menangani state loading/offline secara elegan.
Modul 2

Task Prompt: PWA Manifest & Workbox Setup

[ROLE]: Senior Frontend & PWA Architect
[CONTEXT]: Proyek Vite + React TypeScript dengan Tailwind CSS di Antigravity IDE. Kita ingin mengaktifkan PWA dengan dukungan offline penuh dan install banner.
[INSTRUCTION]:
1. Buat konfigurasi 'vite.config.ts' yang mengintegrasikan 'vite-plugin-pwa' (VitePWA).
2. Konfigurasikan Web App Manifest:
   - name: "Smart Finance PWA"
   - short_name: "SmartFinance"
   - display: "standalone"
   - theme_color: "#09090b"
   - background_color: "#09090b"
   - orientation: "portrait"
   - icons: icon-192x192.png, icon-512x512.png (termasuk purpose: "any maskable")
3. Buat Workbox runtime caching untuk Google Fonts dan aset statis.
4. Buat komponen React 'src/components/InstallPrompt.tsx' yang menangani event 'beforeinstallprompt' untuk Android/Desktop serta mendeteksi Safari iOS untuk instruksi manual ("Add to Home Screen").
[CONSTRAINT]: Tulis seluruh isi file secara lengkap. Pastikan TypeScript types untuk event PWA ditangani dengan rapi tanpa error 'Property beforeinstallprompt does not exist'.
Modul 3

Task Prompt: Skema PostgreSQL & Row Level Security

[ROLE]: Supabase Database Architect & Security Specialist
[CONTEXT]: Aplikasi Manajemen Catatan & Keuangan Pribadi multi-user di Supabase PostgreSQL.
[INSTRUCTION]:
1. Buat script SQL DDL lengkap untuk:
   - Tabel 'profiles' (id UUID references auth.users on delete cascade, full_name TEXT, avatar_url TEXT, updated_at TIMESTAMPTZ).
   - Tabel 'transactions' (id UUID primary key default gen_random_uuid(), user_id UUID references auth.users on delete cascade not null, title TEXT not null, amount NUMERIC(12,2) not null, type TEXT check (type in ('income', 'expense')), category TEXT, created_at TIMESTAMPTZ default now()).
2. Buat PostgreSQL Trigger agar saat user baru sign up di auth.users, otomatis dibuat baris data di tabel 'public.profiles'.
3. Aktifkan Row Level Security (RLS) pada tabel 'profiles' dan 'transactions'.
4. Tulis RLS Policies granular (SELECT, INSERT, UPDATE, DELETE) dengan kondisi keamanan ketat: user hanya boleh melihat dan mengelola data miliknya sendiri (auth.uid() = user_id).
5. Buat index performa pada kolom 'user_id' dan 'created_at'.
[CONSTRAINT]: Hanya berikan script SQL siap eksekusi di Supabase SQL Editor. Berikan komentar singkat pada setiap policy.
Modul 3

Task Prompt: Auth Context & Protected Route

[ROLE]: Senior React & Supabase Developer
[CONTEXT]: Proyek Vite + React (TypeScript) dengan @supabase/supabase-js dan react-router-dom di Antigravity IDE. File client sudah tersedia di 'src/lib/supabase.ts'.
[INSTRUCTION]:
1. Buat 'src/context/AuthContext.tsx' yang membungkus aplikasi:
   - State: user, session, loading (boolean).
   - Menggunakan 'supabase.auth.onAuthStateChange' untuk auto-sync session.
   - Fungsi helper: signInWithEmail, signUpWithEmail, signInWithOAuth, signOut.
2. Buat Custom Hook 'src/hooks/useAuth.ts' untuk konsumsi AuthContext dengan aman.
3. Buat komponen 'src/components/ProtectedRoute.tsx' yang memvalidasi session:
   - Jika loading = true, tampilkan skeleton/spinner minimalis bergaya Tailwind.
   - Jika user = null, redirect ke '/login' dengan state URL asal.
   - Jika user aktif, render children / Outlet.
[CONSTRAINT]: Tulis seluruh implementasi TypeScript secara lengkap tanpa any. Tangani error auth dengan return type yang jelas.
Emergency Rescue Protocol

Skenario Darurat & Prompt Pendek Siap Pakai

Prompt ringkas berakurasi tinggi untuk mengatasi krisis coding umum dalam hitungan detik.

8 Quick-Fix Prompts
Darurat 01

Memecah File Terlalu Panjang (>300 Baris)

Gunakan saat komponen monolitik sulit di-maintain dan AI mulai sering memotong kode.

File [NAMA_FILE.tsx] saat ini terlalu panjang dan monolitik. Tolong lakukan surgical refactoring:
1. Ekstrak logic state dan handler ke custom hook di 'src/hooks/use[NamaFeature].ts'.
2. Pecah sub-komponen UI menjadi komponen atomik di folder 'src/components/[Feature]/'.
3. Jadikan [NAMA_FILE.tsx] hanya sebagai orchestrator yang bersih (< 80 baris).
Berikan kode file-per-file secara lengkap tanpa mengubah flow logic yang sudah berjalan.
Darurat 02

Membersihkan Unused Imports & Ghost Variables

Gunakan saat linter TypeScript / ESLint memunculkan banyak warning import mati.

Periksa kode berikut pada file [NAMA_FILE.tsx]. Hapus semua unused imports, ghost variables, dan redundant console.log. Urutkan import secara rapi: (1) React/Core, (2) Third-party libs, (3) Internal modules/hooks, (4) Types/interfaces. Tuliskan kembali file secara utuh dan clean.
Darurat 03

Memperbaiki Halusinasi Tipe Data TypeScript

Gunakan saat AI mengarang nama field atau property objek yang tidak ada di database.

TypeScript Error: Property '[NAMA_FIELD]' does not exist on type '[NAMA_TYPE]'.
Berikut adalah kontrak interface sebenarnya di 'database.types.ts':
```typescript
[PASTE_INTERFACE_ASLI]
```
Sesuaikan seluruh akses property pada [NAMA_FILE.tsx] agar 100% strictly type-safe sesuai interface asli di atas tanpa menggunakan casting 'as any'.
Darurat 04

Mengatasi Infinite Re-render Loop di React

Gunakan saat browser membeku dengan error "Maximum update depth exceeded".

Browser mendeteksi error: 'Too many re-renders. React limits the number of renders to prevent an infinite loop'.
Berikut kode komponen saya:
```tsx
[PASTE_KODE_KOMPONEN]
```
Analisis dependency array pada useEffect/useCallback/useMemo dan state setter yang terpanggil secara synchronous saat render. Perbaiki dependency loop dan kembalikan kode yang sudah aman.
Darurat 05

Supabase RLS Error 42501 (Permission Denied)

Gunakan saat query Supabase menghasilkan empty array atau permission denied.

Query Supabase gagal dengan error: 'new row violates row-level security policy for table [NAMA_TABEL]' (code 42501).
Operasi yang dijalankan: [INSERT / SELECT / UPDATE / DELETE].
Payload data: [CONTOH_JSON_DATA].
Tolong tuliskan ulang script SQL RLS Policy yang tepat untuk tabel ini agar mengizinkan authenticated user yang sedang login (auth.uid()) melakukan operasi ini dengan aman.
Darurat 06

PWA Service Worker Terjebak Cache Lama

Gunakan saat update fitur frontend tidak muncul di user karena cache service worker agresif.

Aplikasi PWA mengalami masalah 'stale cache', perubahan kode baru tidak otomatis ter-refresh pada browser client.
Tolong konfigurasi 'registerType: "autoUpdate"' atau buat komponen 'ReloadPrompt.tsx' menggunakan hook 'useRegisterSW' dari 'virtual:pwa-register/react' yang memunculkan toast banner 'Versi baru tersedia. [Update Sekarang]' dan memicu 'updateServiceWorker(true)'.
Darurat 07

Realtime Listener Duplikat / Memory Leak

Gunakan saat event Realtime Supabase ter-trigger berkali-kali secara eksponensial.

Supabase channel realtime saya menerima pesan berulang (duplikat).
Berikut hook saya:
```tsx
[PASTE_HOOK_REALTIME]
```
Pastikan channel subscription memiliki 'supabase.removeChannel(channel)' pada return cleanup function di useEffect agar tidak terjadi memory leak dan duplicate listener saat re-mount.
Darurat 08

Surgical Diff Fix (Tanpa Merusak Kode Lain)

Gunakan saat AI merombak baris kode yang sudah benar saat memperbaiki bug kecil.

PERINGATAN: Jangan merombak ulang struktur file [NAMA_FILE.tsx]. Kode lainnya sudah bekerja sempurna.
Hanya lakukan perbaikan spesifik pada fungsi '[NAMA_FUNGSI]' untuk menyelesaikan bug:
Bug: [DESKRIPSI BUG].
Tampilkan HANYA fungsi tersebut atau seluruh file dengan perubahan minimal yang presisi.
