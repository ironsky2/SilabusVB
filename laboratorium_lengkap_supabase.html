LAB 01 — SQL Schema & DDL (Data Definition Language)

Merancang struktur database PostgreSQL, relasi Foreign Key, UUID Primary Key, Triggers, dan Indexes.

📚 A. Teori Fundamental

Database adalah tempat penyimpanan data permanen. Supabase didukung oleh PostgreSQL—mesin database kelas dunia yang digunakan Netflix, Spotify, dan GitHub.

🏪 Analogi: Minimarket dengan Sistem Gudang

• GUDANG = Database PostgreSQL.
• RAK PRODUK = Tabel (profiles, categories, transactions).
• BARIS BARANG = Record (baris data).
• LABEL RAK = Kolom / Field (id, amount, created_at).
• SATPAM OTOMATIS = Trigger (langsung buatkan kartu anggota saat pembeli baru mendaftar).

Konsep Definisi Sederhana Analogi Dunia Nyata
TABLE Tempat simpan satu jenis data terstruktur Rak khusus di gudang
PRIMARY KEY Nomor unik identitas setiap baris (UUID) Barcode produk unik
FOREIGN KEY Kolom yang menunjuk ke baris tabel lain Kode supplier yang tertera di kardus
TRIGGER Fungsi otomatis yang berjalan saat event terjadi Sensor pintu otomatis menyambut tamu
INDEX Struktur pencarian cepat data Daftar isi buku tebal

LAB 02 — Row Level Security (RLS)

Mengisolasi akses data antar pengguna di level kernel database PostgreSQL dengan auth.uid().

📚 A. Teori Fundamental

Row Level Security (RLS) adalah fitur PostgreSQL yang menentukan siapa yang boleh melihat/mengubah baris mana secara otomatis di server database.

🏦 Analogi: Brankas Pribadi vs Brankas Terbuka

• TANPA RLS: Semua orang membuka brankas yang sama. Query SELECT * FROM transactions mengembalikan seluruh data milik semua user di dunia (Sangat Berbahaya!).
• DENGAN RLS: Nasabah Ani query ke database, PostgreSQL otomatis menyisipkan WHERE user_id = auth.uid() di balik layar sehingga Ani hanya melihat transaksinya sendiri.

Operasi Sintaks Kebijakan (Policy) Fungsi Validasi
SELECT USING (user_id = auth.uid()) Baris mana saja yang boleh dibaca
INSERT WITH CHECK (user_id = auth.uid()) Data baru apa yang boleh disimpan
UPDATE USING (...) WITH CHECK (...) Baris mana yang boleh diubah nilainya
DELETE USING (user_id = auth.uid()) Baris mana yang boleh dihapus

LAB 03 — .env Setup & Supabase Client Singleton

Konfigurasi variabel lingkungan yang aman di Vite + React TypeScript dan Singleton Pattern.

📚 A. Teori Fundamental

🔐 Anon Key vs Service Role Key

• Anon Key (VITE_SUPABASE_ANON_KEY): Kunci publik yang aman diletakkan di browser frontend karena seluruh aksesnya dibatasi oleh RLS.
• Service Role Key: Kunci master backend yang membypass semua RLS. DILARANG KERAS dimasukkan ke file frontend atau di-commit ke GitHub!

Aspek Tanpa Singleton (Boros Memori) Dengan Singleton Pattern (Efisien)
Inisialisasi createClient() dipanggil ulang di setiap komponen Dibuat 1x di src/lib/supabase.ts lalu diekspor
Koneksi WebSocket Bisa membuat puluhan koneksi terduplikasi Satu koneksi tunggal yang dipakai bersama

LAB 05 — Realtime Subscription (WebSocket)

Sinkronisasi data multi-tab instan tanpa refresh dan teknik Zero-Memory-Leak cleanup.

📚 A. Teori Fundamental

📺 Analogi: DVD Player vs Siaran TV Langsung

• HTTP Request Biasa (DVD): Browser meminta data, server merespons, selesai. Jika ada perubahan baru di database, browser tidak tahu sebelum halaman di-refresh.
• WebSocket Realtime (Siaran TV): Jalur komunikasi dua arah terbuka terus menerus. Begitu ada baris baru diinsert ke tabel database, Supabase langsung mendorong (*push*) event ke UI secara instan.

⚠️ PERINGATAN MEMORY LEAK: Setiap kali memanggil supabase.channel(...).subscribe(), Anda WAJIB mengembalikan supabase.removeChannel(channel) di fungsi cleanup useEffect agar koneksi ditutup saat komponen unmount!

📚 A. Teori Fundamental

🗄️ Public vs Private Storage Bucket

• Public Bucket (e.g. avatars): URL file dapat diakses publik via browser tanpa token (cocok untuk gambar foto profil atau banner publik).
• Private Bucket (e.g. invoices): File hanya dapat diakses melalui *Signed URL* yang memiliki batas waktu kadaluarsa (cocok untuk berkas rahasia).

Lampiran: Referensi Cepat Supabase JS v2 & Dokter Error

Rangkuman sintaks esensial dan panduan pemecahan error paling umum.

⚡ Quick Reference Cheat Sheet

SUPABASE CLIENT JS v2 QUICK CHEAT SHEET 
// 1. AUTH
await supabase.auth.signInWithPassword({ email, password });
await supabase.auth.signInWithOAuth({ provider: 'google' });
await supabase.auth.signUp({ email, password });
await supabase.auth.signOut();
const { data: { session } } = await supabase.auth.getSession();
supabase.auth.onAuthStateChange((event, session) => { /* update auth state */ });

// 2. QUERY BUILDER (SELECT)
const { data, error } = await supabase
  .from('transactions')
  .select('*, categories(name, color)')
  .eq('user_id', user.id)
  .order('date', { ascending: false })
  .limit(20);

// 3. INSERT & OPTIMISTIC
const { data, error } = await supabase
  .from('transactions')
  .insert({ user_id: user.id, amount: 50000, type: 'expense' })
  .select().single();

// 4. STORAGE
await supabase.storage.from('avatars').upload(path, file, { upsert: true });
const { data: { publicUrl } } = supabase.storage.from('avatars').getPublicUrl(path);

// 5. REALTIME (SELALU CLEANUP!)
const channel = supabase.channel('realtime_tx')
  .on('postgres_changes', { event: 'INSERT', table: 'transactions' }, (payload) => {
    // update state
  })
  .subscribe();
supabase.removeChannel(channel); // <- WAJIB saat unmount!
