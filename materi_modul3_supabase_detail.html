01

Menulis Skema SQL & RLS Policies di Supabase

DDL Tables · Foreign Keys · Triggers · Row Level Security

Konsep: Apa itu DDL & Mengapa RLS Sangat Penting?

📋 DDL (Data Definition Language):

DDL adalah sekumpulan perintah SQL untuk mendefinisikan struktur database — bukan mengisi data. Meliputi: CREATE TABLE, ALTER TABLE, DROP TABLE. Kita mendefinisikan kolom, tipe data, relasi (Foreign Key), dan batasan (Constraints) di sini.

🔐 Row Level Security (RLS):

RLS adalah fitur PostgreSQL yang memungkinkan Anda mendefinisikan aturan per baris data. Artinya, user A secara mutlak tidak bisa membaca data milik user B — meski keduanya menggunakan anon key yang sama. Ini adalah garis pertahanan utama di backend Supabase.

Kedua perintah SQL di bawah ini ditulis identik. Yang berbeda adalah apa yang PostgreSQL kembalikan — tergantung apakah RLS aktif atau tidak.

🔴 TANPA RLS (Berbahaya!)
SELECT * FROM transactions;

PostgreSQL mengeksekusi query apa adanya — tanpa filter kepemilikan. Hasilnya:

user_id title amount
user-A (kamu) Gaji Maret 5.000.000
user-B (orang lain!) Bonus Tahunan 20.000.000
user-C (orang lain!) Beli Saham 15.000.000

⚠️ User A bisa membaca data finansial user B & C!

🟢 DENGAN RLS (Aman!)
SELECT * FROM transactions;
↓ PostgreSQL otomatis menambahkan filter ini ↓
WHERE user_id = auth.uid() — ID user yang login

PostgreSQL menambahkan kondisi WHERE user_id = auth.uid() secara otomatis di belakang layar. Hasilnya:

user_id title amount
user-A (kamu) Gaji Maret 5.000.000
user-B Bonus Tahunan 20.000.000
user-C Beli Saham 15.000.000

Baris dicoret = tidak pernah dikirim ke browser, tersaring di level database.

✅ Hanya data milik user A yang dikembalikan.

💡 Inti perbedaannya: Query SQL yang Anda tulis memang sama persis. Namun saat RLS aktif, PostgreSQL menyelipkan filter WHERE user_id = auth.uid() secara otomatis sebelum data diambil — tanpa perlu Anda tulis di kode frontend. Filter ini ada di level database, sehingga tidak bisa dimanipulasi dari sisi browser.

-- 1. FUNCTION: Auto-update timestamp saat row di-update
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 2. TABEL: profiles (satu baris per user, relasi ke auth.users)
CREATE TABLE IF NOT EXISTS public.profiles (
  id          UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY,
  full_name   TEXT,
  avatar_url  TEXT,
  updated_at  TIMESTAMPTZ DEFAULT now()
);

-- Trigger: update timestamp otomatis di profiles
CREATE OR REPLACE TRIGGER profiles_updated_at
  BEFORE UPDATE ON public.profiles
  FOR EACH ROW EXECUTE FUNCTION update_updated_at_column();

-- 3. TABEL: categories (tiap user bisa punya kategori sendiri)
CREATE TABLE IF NOT EXISTS public.categories (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  color       TEXT DEFAULT '#6366f1',
  icon        TEXT DEFAULT 'tag',
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 4. TABEL: transactions (data utama catatan keuangan)
CREATE TABLE IF NOT EXISTS public.transactions (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  category_id UUID REFERENCES public.categories(id) ON DELETE SET NULL,
  title       TEXT NOT NULL,
  amount      NUMERIC(15,2) NOT NULL,
  type        TEXT NOT NULL CHECK (type IN ('income', 'expense')),
  note        TEXT,
  date        DATE DEFAULT CURRENT_DATE,
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 5. FUNCTION + TRIGGER: Auto-buat profile saat user sign up
CREATE OR REPLACE FUNCTION handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.profiles (id, full_name, avatar_url)
  VALUES (
    NEW.id,
    NEW.raw_user_meta_data ->> 'full_name',
    NEW.raw_user_meta_data ->> 'avatar_url'
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE OR REPLACE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION handle_new_user();

-- 6. INDEX performa (mempercepat query filter by user_id & date)
CREATE INDEX IF NOT EXISTS idx_transactions_user_id ON public.transactions(user_id);
CREATE INDEX IF NOT EXISTS idx_transactions_date     ON public.transactions(date DESC);
CREATE INDEX IF NOT EXISTS idx_categories_user_id    ON public.categories(user_id);
ON DELETE CASCADE

Saat user dihapus dari auth.users, semua data terkait (profiles, categories, transactions) ikut terhapus otomatis. Tidak ada data orphan yang menggantung.

SECURITY DEFINER

Function handle_new_user dijalankan dengan hak akses owner function (superuser), bukan hak akses user biasa, sehingga bisa menginsert ke public.profiles tanpa hambatan RLS.

INDEX Performa

Index pada user_id dan date mempercepat query filter seperti WHERE user_id = ? AND date >= ? dari O(n) full-scan menjadi O(log n) B-tree lookup.

02

Row Level Security (RLS) Policies

Enable RLS · Granular Policies per Operation · Verifikasi

Mengapa RLS Harus Diaktifkan Sebelum Aplikasi Digunakan?

Supabase menggunakan PostgreSQL RLS sebagai firewall database tingkat baris. Tanpa RLS aktif, seluruh data tabel bisa diakses siapapun yang memiliki anon_key — termasuk pengguna yang belum login.

Policy RLS dievaluasi secara otomatis oleh PostgreSQL sebelum query mencapai data. Ini berarti proteksi terjadi di level database, bukan di kode aplikasi — jauh lebih aman karena tidak bisa di-bypass oleh bug frontend.

-- ==============================================================
-- ROW LEVEL SECURITY POLICIES — Smart Finance PWA
-- ==============================================================

-- ---- PROFILES TABLE ----
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;

-- User hanya bisa melihat profil milik dirinya sendiri
CREATE POLICY "profiles: user can view own profile"
  ON public.profiles FOR SELECT

CREATE POLICY "profiles: user can update own profile"

// src/context/AuthContext.tsx
import {
  createContext, useContext, useEffect, useState, useCallback
} from 'react';
import type { ReactNode } from 'react';
import type { AuthError, Session, User } from '@supabase/supabase-js';
import { supabase } from '../lib/supabase';
import type { Profile } from '../types/database.types';

interface AuthResult {
  error: AuthError | null;
}

interface AuthContextType {
  user:              User | null;
  session:           Session | null;
  profile:           Profile | null;
  loading:           boolean;
  signUpWithEmail:   (email: string, password: string, fullName: string) => Promise<AuthResult>;
  signInWithEmail:   (email: string, password: string) => Promise<AuthResult>;
  signInWithGoogle:  () => Promise<AuthResult>;
  signOut:           () => Promise<void>;
}

const AuthContext = createContext<AuthContextType | undefined>(undefined);

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user,    setUser]    = useState<User    | null>(null);
  const [session, setSession] = useState<Session | null>(null);
  const [profile, setProfile] = useState<Profile | null>(null);
  const [loading, setLoading] = useState<boolean>(true);

  // Fetch profile dari public.profiles saat user berubah
  const fetchProfile = useCallback(async (userId: string) => {
    const { data } = await supabase
      .from('profiles')
      .select('*')
      .eq('id', userId)
      .single();
    setProfile(data);
  }, []);

  useEffect(() => {
    // 1. Cek session yang sudah tersimpan di localStorage saat pertama kali mount
    supabase.auth.getSession().then(({ data: { session } }) => {
      setSession(session);
      setUser(session?.user ?? null);
      if (session?.user) fetchProfile(session.user.id);
      setLoading(false);
    });

    // 2. Subscribe perubahan auth state secara realtime
    const { data: { subscription } } = supabase.auth.onAuthStateChange(
      (event, session) => {
        setSession(session);
        setUser(session?.user ?? null);
        if (session?.user) {
          fetchProfile(session.user.id);
        } else {
          setProfile(null);
        }
        setLoading(false);
      }
    );

    // 3. Cleanup — lepas listener saat AuthProvider unmount
    return () => subscription.unsubscribe();
  }, [fetchProfile]);

  const signUpWithEmail = async (
    email: string, password: string, fullName: string
  ): Promise<AuthResult> => {
    const { error } = await supabase.auth.signUp({
      email,
      password,
      options: { data: { full_name: fullName } },
    });
    return { error };
  };

  const signInWithEmail = async (
    email: string, password: string
  ): Promise<AuthResult> => {
    const { error } = await supabase.auth.signInWithPassword({ email, password });
    return { error };
  };

  const signInWithGoogle = async (): Promise<AuthResult> => {
    const { error } = await supabase.auth.signInWithOAuth({
      provider: 'google',
      options: { redirectTo: `${window.location.origin}/dashboard` },
    });
    return { error };
  };

  const signOut = async (): Promise<void> => {
    await supabase.auth.signOut();
  };

  return (
    <AuthContext.Provider value={{ user, session, profile, loading, signUpWithEmail, signInWithEmail, signInWithGoogle, signOut }}>
      {children}
    </AuthContext.Provider>
  );
}

// Custom hook — safe consumer dengan error jika dipakai di luar Provider
export function useAuth(): AuthContextType {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth harus digunakan di dalam <AuthProvider>');
  }
  return context;
}

// src/components/ProtectedRoute.tsx
import { Navigate, Outlet, useLocation } from 'react-router-dom';
import { useAuth } from '../context/AuthContext';

export function ProtectedRoute() {
  const { user, loading } = useAuth();
  const location = useLocation();

  // 1. Tampilkan loading spinner saat session masih diperiksa
  if (loading) {
    return (
      <div className="min-h-screen bg-slate-50 flex items-center justify-center">
        <div className="flex flex-col items-center gap-3">
          <div className="w-8 h-8 border-2 border-indigo-600 border-t-transparent rounded-full animate-spin" />
          <p className="text-xs text-slate-400 font-medium">Memeriksa sesi...</p>
        </div>
      </div>
    );
  }

  // 2. Redirect ke /login jika tidak ada user aktif
  // state.from menyimpan halaman asal untuk redirect balik setelah login
  if (!user) {
    return <Navigate to="/login" state={{ from: location.pathname }} replace />;
  }

  // 3. Render halaman tujuan (nested routes via Outlet)
  return <Outlet />;
}

Realtime Subscription Hook dengan Safe Cleanup

supabase.channel() · CRUD Operations · Memory Leak Prevention · Optimistic Updates

Konsep: Bagaimana Supabase Realtime Bekerja?

WebSocket Channel: Supabase membuka koneksi WebSocket persisten antara browser dan server. Setiap perubahan database (INSERT, UPDATE, DELETE) diteruskan ke semua subscriber yang aktif dalam milidetik.

Memory Leak Risk: Jika listener WebSocket tidak dibersihkan saat komponen React di-unmount, listener akan terus aktif di background — menimbulkan duplicate events dan konsumsi memori yang bocor setiap kali komponen re-mount.

// src/hooks/useTransactions.ts
import { useState, useEffect, useCallback } from 'react';
import { supabase } from '../lib/supabase';
import { useAuth } from '../context/AuthContext';
import type {
  Transaction, TransactionInsert, TransactionUpdate, TransactionWithCategory
} from '../types/database.types';

interface UseTransactionsReturn {
  transactions:   TransactionWithCategory[];
  isLoading:      boolean;
  isSubmitting:   boolean;
  error:          string | null;
  addTransaction:    (data: TransactionInsert) => Promise<{ error: string | null }>;
  updateTransaction: (id: string, data: TransactionUpdate) => Promise<{ error: string | null }>;
  deleteTransaction: (id: string) => Promise<{ error: string | null }>;
  refetch:            () => Promise<void>;
}

export function useTransactions(): UseTransactionsReturn {
  const { user } = useAuth();

  const [transactions, setTransactions] = useState<TransactionWithCategory[]>([]);
  const [isLoading,     setIsLoading]     = useState<boolean>(true);
  const [isSubmitting,  setIsSubmitting]  = useState<boolean>(false);
  const [error,         setError]         = useState<string | null>(null);

  // -------- FETCH (Initial + Manual Refetch) --------
  const fetchTransactions = useCallback(async () => {
    if (!user) { setTransactions([]); setIsLoading(false); return; }

    setIsLoading(true);
    setError(null);

    const { data, error: fetchError } = await supabase
      .from('transactions')
      .select('*, categories(*)')           // Join ke tabel categories
      .eq('user_id', user.id)
      .order('date', { ascending: false });

    if (fetchError) {
      setError(fetchError.message);
    } else {
      setTransactions((data as TransactionWithCategory[]) ?? []);
    }
    setIsLoading(false);
  }, [user]);

  // -------- REALTIME SUBSCRIPTION --------
  useEffect(() => {
    fetchTransactions();

    if (!user) return;

    // Subscribe hanya ke perubahan transaksi milik user yang sedang login
    const channel = supabase
      .channel(`transactions_${user.id}`)
      .on(
        'postgres_changes',
        {
          event:  '*',                   // INSERT | UPDATE | DELETE
          schema: 'public',
          table:  'transactions',
          filter: `user_id=eq.${user.id}`, // Filter server-side per user
        },
        (payload) => {
          const { eventType, new: newRow, old: oldRow } = payload;

          if (eventType === 'INSERT') {
            // Refetch untuk mendapatkan join data (categories)
            fetchTransactions();
          } else if (eventType === 'UPDATE') {
            setTransactions(prev =>
              prev.map(t => t.id === (newRow as Transaction).id
                ? { ...t, ...(newRow as Transaction) }
                : t
              )
            );
          } else if (eventType === 'DELETE') {
            setTransactions(prev =>
              prev.filter(t => t.id !== (oldRow as Transaction).id)
            );
          }
        }
      )
      .subscribe();

    // ← CLEANUP WAJIB: lepas channel saat komponen unmount atau user berubah
    return () => {
      supabase.removeChannel(channel);
    };
  }, [user, fetchTransactions]);

  // -------- ADD --------
  const addTransaction = async (data: TransactionInsert) => {
    if (!user) return { error: 'User tidak login' };
    setIsSubmitting(true);

    const { error: insertError } = await supabase
      .from('transactions')
      .insert({ ...data, user_id: user.id });

    setIsSubmitting(false);
    return { error: insertError?.message ?? null };
  };

  // -------- UPDATE --------
  const updateTransaction = async (id: string, data: TransactionUpdate) => {
    setIsSubmitting(true);

    const { error: updateError } = await supabase
      .from('transactions')
      .update(data)
      .eq('id', id)
      .eq('user_id', user?.id ?? ''); // Double-check ownership

    setIsSubmitting(false);
    return { error: updateError?.message ?? null };
  };

  // -------- DELETE (Optimistic) --------
  const deleteTransaction = async (id: string) => {
    // Optimistic update: hapus dari state dulu sebelum konfirmasi server
    const snapshot = [...transactions];
    setTransactions(prev => prev.filter(t => t.id !== id));

    const { error: deleteError } = await supabase
      .from('transactions')
      .delete()
      .eq('id', id)
      .eq('user_id', user?.id ?? '');

    if (deleteError) {
      // Rollback ke snapshot sebelumnya jika server error
      setTransactions(snapshot);
      return { error: deleteError.message };
    }

    return { error: null };
  };

  return {
    transactions,
    isLoading,
    isSubmitting,
    error,
    addTransaction,
    updateTransaction,
    deleteTransaction,
    refetch: fetchTransactions,
  };
}

// src/pages/DashboardPage.tsx — Contoh konsumsi useTransactions
import { useTransactions } from '../hooks/useTransactions';

export default function DashboardPage() {
  const {
    transactions,
    isLoading,
    isSubmitting,
    error,
    addTransaction,
    deleteTransaction,
  } = useTransactions();

  const handleAdd = async () => {
    const { error } = await addTransaction({
      user_id: '',       // Hook akan mengisi user_id otomatis
      title:  'Belanja Groceries',
      amount: 150000,
      type:   'expense',
    });
    if (error) console.error('Gagal menambah:', error);
  };

  if (isLoading) return <div>Memuat data...</div>;
  if (error) return <div className="text-rose-500">Error: {error}</div>;

  return (
    <ul>
      {transactions.map(trx => (
        <li key={trx.id} className="flex justify-between">
          <span>{trx.title} — Rp {trx.amount.toLocaleString('id-ID')}</span>
          <button
            onClick={() => deleteTransaction(trx.id)}
            disabled={isSubmitting}
          >
            Hapus
          </button>
        </li>
      ))}
    </ul>
  );
}
