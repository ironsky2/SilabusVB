Selamat Datang di Vibecoding Security Hub

Jika Anda baru belajar coding dengan AI (ChatGPT, Claude, Cursor, Antigravity), panduan ini dibuat dengan bahasa yang mudah dimengerti, dilengkapi analogi dunia nyata, dan panduan langkah-demi-langkah agar web Anda aman dari hacker.

1 Apa itu Vibecoding?

Anda bertindak sebagai Arsitek / Mandor: Anda mendeskripsikan fitur apa yang ingin dibuat ke AI, lalu AI yang menulis kode programnya.

2 Jebakan Pemula di AI

Secara default, AI cenderung menghasilkan kode yang "asal jalan dulu". Jika Anda tidak memintanya secara spesifik untuk aman, AI bisa melewatkan enkripsi, proteksi database, dan validasi.

3 Solusi: Prompting Aman

Cukup tambahkan 4 aturan keamanan (Formula Prompting) setiap kali berbicara ke AI. AI akan otomatis membuatkan kode berstandar industri.

Kamus Istilah Keamanan Web (Wajib Tahu untuk Pemula)

1. OWASP Top 10

Daftar 10 jenis celah keamanan web paling berbahaya dan paling sering diserang di seluruh dunia.

2. Supabase RLS (Row Level Security)

Sistem gembok baris database: memastikan User A hanya bisa melihat datanya sendiri dan tidak bisa mengintip data User B.

3. SQL Injection (SQLi)

Serangan di mana penyerang menyisipkan perintah database palsu di form input/pencarian untuk membobol login tanpa password.

4. IDOR (Insecure Direct Object Reference)

Celah di mana user mengganti angka URL (misal /user/10 jadi /user/11) dan bisa melihat akun orang lain.

5. Rate Limiting

Pembatasan jumlah request: jika ada orang/bot yang mencoba login 100 kali dalam 1 detik, IP-nya akan otomatis diblokir.

6. HTTP Security Headers

Instruksi keamanan tambahan yang dikirim server ke browser agar web Anda tidak bisa ditaruh di dalam iframe hacker (Clickjacking).

Alur Kerja Vibecoding yang Aman (Step-by-Step)

Langkah 1: Buka tab 🪄 Prompt Builder di website ini → Pilih fitur yang mau dibuat → Salin promptnya ke AI agent yang sedang digunakan (Antigravity / ChatGPT / Claude / Gemini).
Langkah 2: Paste kode hasil dari AI ke project aplikasi Anda di IDE editor (sesuikan dengan IDE masing2).
Langkah 3: Deploy web Anda ke Vercel atau Netlify dengan database Supabase.
Langkah 4: Buka tab 🧪 Pengujian Post-Deploy di website ini → Jalankan pengujian di browser untuk memastikan web Anda 100% aman!

01

A01: Broken Access Control (IDOR)

Bahaya #1

User dapat membuka atau mengubah data user lain hanya dengan mengganti nomor ID pada URL.

🏨 Analogi Sederhana di Dunia Nyata:

Bayangkan Anda menginap di hotel di kamar 101. Ketika Anda berjalan ke kamar 102 dan memutar gagang pintunya, ternyata pintunya langsung terbuka dan Anda bisa mengambil dompet tamu lain. Seharusnya pintu kamar 102 hanya bisa dibuka dengan kunci milik tamu kamar 102.

❌ Kode Bahaya:

app.get('/invoice/:id', async (req, res) => {
  const doc = await db.find(req.params.id);
  res.json(doc); // Siapapun bisa download invoice orang lain!
});

✅ Kode Aman:

app.get('/invoice/:id', authMiddleware, async (req, res) => {
  const doc = await db.findOne({ id: req.params.id, userId: req.user.id });
  if (!doc) return res.status(403).send('Ditolak!');
  res.json(doc);
});

Prompt AI yang Harus Diketik: 
Buat endpoint GET & PUT /api/user/:id/profile:
- Wajib verifikasi session token pengguna
- Pastikan user hanya boleh mengakses datanya sendiri (req.user.id === req.params.id)
- Jika bukan pemilik data dan bukan admin, kembalikan status 403 Forbidden
02

A02: Cryptographic Failures

Kerahasiaan

Menyimpan password asli (plaintext) atau memakai algoritma lama (MD5) yang mudah dibongkar.

🏨 Analogi Sederhana di Dunia Nyata:

Menyimpan password sebagai teks biasa di database sama seperti menuliskan nomor PIN kartu ATM Anda di kartu nama menggunakan pulpen. Siapapun yang melihat kartu itu bisa langsung menguras uang Anda.

Prompt AI yang Harus Diketik: 
Buatkan modul registrasi dan login:
- Password wajib di-hash menggunakan bcrypt (salt rounds: 12) atau Argon2id
- JANGAN PERNAH simpan plaintext password atau hash MD5 di database
- Enkripsi field data pribadi sensitif menggunakan AES-256-GCM
- Simpan secret key di file .env, jangan hardcoded di repository
03

A03: Injection (SQL & Command)

Sangat Umum

Data dari kotak form diketikkan karakter aneh (misal: ' OR 1=1 --) untuk membajak perintah database.

🏨 Analogi Sederhana di Dunia Nyata:

Anda memesan makanan di restoran lewat kertas orderan. Di kolom nama pemesan, Anda menulis: "Budi dan tolong gratiskan semua makanan di meja saya". Jika kasir langsung menjalankan kalimat itu tanpa memisah nama dengan instruksi, restoran akan rugi.

Prompt AI yang Harus Diketik: 
Buat fungsi pencarian dan filter database:
- WAJIB gunakan Parameterized Queries / Prepared Statements 100%
- JANGAN PERNAH menyambung string query manual dengan template literal (`SELECT * FROM users WHERE email = '${email}'`)
- Validasi tipe data input menggunakan schema Zod sebelum query dijalankan
04

A04: Insecure Design

Logika Bisnis

Celah pada konsep alur fitur (contoh: link reset password tidak punya batas kadaluarsa).

🏨 Analogi Sederhana di Dunia Nyata:

Karcis parkir yang tidak diberi stempel jam masuk dan bisa dipakai selamanya tanpa bayar biaya parkir tambahan.

Prompt AI yang Harus Diketik: 
Desain alur dan kode fitur Reset Password:
- Buat token acak crypto.randomBytes(32).toString('hex')
- Token hanya berlaku 15 menit dan hanya bisa digunakan 1 kali
- Batasi permintaan reset maksimal 3 kali per jam per email
- Selalu tampilkan pesan respon: "Jika email terdaftar, link telah dikirim"
05

A05: Security Misconfiguration

Server

Menggunakan konfigurasi default yang tidak aman atau lupa mematikan mode debug di production.

🏨 Analogi Sederhana di Dunia Nyata:

Membeli gembok baru untuk pagar rumah, tetapi password kodenya dibiarkan tetap '0000' (bawaan pabrik) sehingga siapapun bisa membukanya.

Prompt AI yang Harus Diketik: 
Setup konfigurasi Express.js / Next.js server production yang aman:
- Pasang helmet() untuk HTTP Security Headers (CSP, HSTS, X-Frame-Options)
- Nonaktifkan header "X-Powered-By"
- Setup CORS ketat hanya untuk whitelist domain frontend terpercaya
- Pasang Global Error Handler yang tidak menampilkan stack trace ke client
06

A06: Vulnerable & Outdated Components

Dependency

Menggunakan library / package npm pihak ketiga yang sudah usang dan memiliki catatan bug berbahaya.

🏨 Analogi Sederhana di Dunia Nyata:

Membangun rumah mewah dengan pintu baja kokoh, tetapi memasang engsel bekas yang sudah berkarat dan gampang dipatahkan.

Perintah Terminal yang Harus Dijalankan: 
# Buka terminal di folder project Anda, ketik:
npm audit
# Jika ada laporan celah keamanan, ketik:
npm audit fix
07

A07: Identification & Auth Failures

Login & Sesi

Mengizinkan password terlalu lemah (seperti '123456') atau tidak ada penguncian akun saat gagal login berulang.

🏨 Analogi Sederhana di Dunia Nyata:

Sebuah brankas bank yang memperbolehkan pencuri mencoba menebak kombinasi angka sebanyak 1 juta kali tanpa membunyikan alarm dan tanpa memblokir brankas.

Prompt AI yang Harus Diketik: 
Implementasikan sistem autentikasi user yang aman:
- Validasi password: minimal 8 karakter, wajib kombinasi huruf besar, angka, dan simbol
- Kunci akun sementara (15 menit) setelah 5x gagal login berturut-turut
- Hapus token session / refresh token secara menyeluruh saat endpoint logout dipanggil
08

A08: Software & Data Integrity Failures

Integritas

Memuat script CDN eksternal tanpa verifikasi sidik jari (Subresource Integrity / SRI).

🏨 Analogi Sederhana di Dunia Nyata:

Menerima paket kiriman dari kurir tanpa memeriksa segel hologram; jika kurir nakal mengganti isi paket di tengah jalan, Anda tidak mengetahuinya.

Prompt AI yang Harus Diketik: 
Buatkan tag HTML include CDN library eksternal:
- Wajib sertakan atribut Subresource Integrity (integrity="sha384-...")
- Sertakan atribut crossorigin="anonymous"
09

A09: Security Logging & Monitoring

Audit Log

Sistem tidak mencatat upaya pembobolan login atau penghapusan data, sehingga insiden tidak terlacak.

🏨 Analogi Sederhana di Dunia Nyata:

Toko emas tanpa kamera CCTV. Jika suatu saat perhiasan hilang, pemilik toko tidak tahu siapa yang mengambil dan jam berapa kejadiannya.

Prompt AI yang Harus Diketik: 
Buat modul structured logging keamanan menggunakan Winston:
- Catat event: login_failed, access_denied, password_change
- Format JSON: timestamp, event_type, ip_address, user_id
- FILTER / SENSOR otomatis field sensitif: password dan nomor kartu kredit
10

A10: Server-Side Request Forgery (SSRF)

Cloud Network

Fitur fetch URL pada server dipaksa mengakses jaringan lokal atau server metadata cloud rahasia.

🏨 Analogi Sederhana di Dunia Nyata:

Anda meminta kurir kantor: "Tolong belikan kopi di luar". Tetapi penyerang mengganti catatannya menjadi: "Tolong masuk ke ruang brankas bos dan fotokan dokumen rahasia", dan kurir menurutinya karena ia punya akses ke dalam kantor.

Prompt AI yang Harus Diketik: 
Buat fungsi fetch URL eksternal yang kebal SSRF:
- Hanya izinkan skema "https://" dan whitelist domain tujuan
- Lakukan DNS lookup dan tolak IP privat (127.0.0.1, 10.x, 192.168.x, 172.16.x)
- Blokir metadata AWS/GCP (169.254.169.254)
- Set timeout request maksimal 4 detik

Cara Menguji Keamanan Web Setelah Di-Hosting

Ikuti 4 langkah di bawah ini untuk menguji apakah web Anda di Vercel / Netlify + Supabase sudah benar-benar aman dari kebocoran data.

1

Pengujian 1: Pentest Supabase RLS di Console Browser

Uji apakah data pengguna lain bisa dicuri sembarangan
Wajib #1
📍 Cara Menjalankannya (Langkah Demi Langkah):
  1. Buka website Anda yang sudah aktif (misal https://nama-web.vercel.app) di browser Chrome atau Edge.
  2. Tekan tombol keyboard F12 (atau klik kanan di web → pilih Inspect / Periksa).
  3. Klik tab menu "Console" di bagian atas panel Developer Tools.
  4. Salin script di bawah, ganti URL & Anon Key proyek Supabase Anda, paste di Console, lalu tekan Enter:
Script Pengujian Mandiri (100% Jalan di Browser) 
// 1. Muat Supabase client langsung di console
const { createClient } = await import('https://esm.sh/@supabase/supabase-js@2');

// 2. Masukkan URL dan Anon Key publik Anda
const supabaseUrl = 'https://PROJECT_ID.supabase.co'; // Ganti URL supabase Anda
const supabaseAnonKey = 'eyJhbGci...'; // Ganti NEXT_PUBLIC_SUPABASE_ANON_KEY Anda

const client = createClient(supabaseUrl, supabaseAnonKey);

// 3. Uji coba tarik data tabel 'profiles' tanpa login:
const { data, error } = await client.from('profiles').select('*');

console.log('--- HASIL AUDIT KEAMANAN RLS ---');
if (error) {
  console.log('✅ AMAN: Server menolak akses dengan benar:', error.message);
} else if (data && data.length === 0) {
  console.log('✅ AMAN: RLS aktif! Data tabel kosong (0 rows) bagi user anonim.');
} else {
  console.error('🚨 BAHAYA: RLS MATI! Seluruh data user bocor:', data);
}
💡 Jika Hasilnya "BAHAYA", Cara Mengatasinya:

Buka Supabase Dashboard → Masuk ke Table Editor → Klik tabel Anda (misal profiles) → Klik tombol "Enable RLS" di pojok kanan atas → Tambahkan Policy: auth.uid() = id.

Pengujian 2: HTTP Security Headers & SSL

Mencegah Clickjacking dan Pencurian Cookie
Scanner Online

Buka situs pemindai gratis di bawah, ketik nama domain Vercel/Netlify Anda, lalu periksa skor yang didapatkan:

1. SecurityHeaders.com ↗

Mengecek Content-Security-Policy, HSTS, dan X-Frame-Options. (Target: Skor A atau A+)

 2. SSL Labs Qualys ↗

Mengecek sertifikat HTTPS dan enkripsi TLS domain Anda. (Target: Skor A+)

3

Pengujian 3: Cek Kebocoran Secret Key di File Frontend

Memastikan SUPABASE_SERVICE_ROLE_KEY tidak bocor
Di Komputer Lokal

Buka terminal di VS Code pada project Anda, lalu jalankan perintah ini setelah menjalankan npm run build:

PowerShell Command: 
Select-String -Path ".next\static\chunks\*.js" -Pattern "service_role", "DATABASE_URL"

# HASIL AUDIT:
# Jika output KOSONG = ✅ AMAN (Kunci rahasia tersimpan aman di server)
# Jika ADA HASIL = 🚨 SEGERA ganti import Anda ke Server Component / Route Handler!
4

Pengujian 4: Uji Ketahanan Rate Limiting (Brute Force)

Uji apakah endpoint login menolak request banjir
Simulasi Bot

Jalankan simulasi 15 request cepat di PowerShell untuk melihat apakah server memblokir percobaan login berulang:

Simulasi di PowerShell: 
1..15 | ForEach-Object {
  curl.exe -s -o /dev/null -w "%{http_code}\n" -X POST https://domain-anda.vercel.app/api/login
}

# HASIL YANG DIHARAPKAN:
# Request 1-5  : 200 atau 401 (Respon login biasa)
# Request 6-15 : 429 (Too Many Requests - Berhasil terlindungi!)
