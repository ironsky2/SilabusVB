👨‍🏫 Pesan Pengajar: Filosofi Vibe Coding dengan Git

Dalam paradigma Vibe Coding, AI adalah rekan programmer (copilot) yang sangat produktif namun dapat membuat kesalahan atau merusak kode yang sudah berfungsi. Git bukan sekadar alat upload ke GitHub, melainkan "Mesin Waktu Penyelamat" (Safety Net) Anda. Dengan menguasai kombinasi init, add, commit, restore, dan push, Anda memiliki kendali penuh 100% untuk mengeksplorasi kode tanpa pernah takut kehilangan karya Anda!

BAGIAN 1: ARSITEKTUR SIKLUS HIDUP GIT

Peta 4 Tahapan Berkas dalam Git & GitHub

Setiap baris kode yang Anda tulis bergerak melalui 4 zona ruang kerja ini sebelum mendarat aman di cloud internet:

ZONA 1 · HARDDISK

Working Directory

Folder tempat Anda mengedit file secara aktif bersama AI. Perubahan masih berstatus Unstaged.

git init git restore . (Discard)
ZONA 2 · ANTREAN FOTO

Staging Area (Index)

Kotak seleksi berkas yang sudah dipilih dan siap diambil fotonya (siap di-commit).

git add . git restore --staged .
ZONA 3 · BRANKAS LOKAL

Local Repo (HEAD)

Koleksi snapshot permanen berlabel di laptop Anda. Memiliki ID Commit & riwayat timestamp.

git commit -m "..." git revert / reset
ZONA 4 · CLOUD INTERNET

GitHub Remote

Gudang brankas online di internet. Tempat backup aman, kolaborasi tim, dan rujukan deployment live.

git push origin main git pull / fetch

01

Modul 1: Inisialisasi Proyek, Konfigurasi Identitas & Proteksi .gitignore

Mempersiapkan fondasi repositori baru, mendaftarkan nama/email pembuat, dan memfilter berkas sensitif

Perintah Terkait: git init git config Keamanan: .gitignore (.env, node_modules)

Jalankan prompt ini saat pertama kali membuat folder proyek baru. AI akan memastikan Git diaktifkan, nama Anda terpasang, dan file rahasia seperti API Key tidak akan bocor ke publik.

PROMPT 1 — INISIALISASI & SETUP AMAN 
Halo Antigravity, saya ingin menginisialisasi sistem pelacakan versi Git untuk proyek yang sedang terbuka ini.

Tolong lakukan langkah-langkah setup berikut:
1. Periksa apakah repositori Git lokal sudah aktif di folder ini. Jika belum, jalankan 'git init'.
2. Buatkan file '.gitignore' standar industri yang lengkap sesuai tech-stack proyek ini (pastikan memblokir .env, .env.local, node_modules/, .DS_Store, dist/, dan folder cache/temporary).
3. Periksa konfigurasi nama (user.name) dan email (user.email) Git saya. Jika belum disetel, bantu setel dengan nama dan email saya.
4. Buat branch utama default dengan nama 'main'.

Setelah selesai, laporkan status repositori awal ini kepada saya dengan bahasa yang ramah dan mudah dipahami.
🔍 Klik untuk melihat perintah Terminal (CLI) yang dijalankan AI di belakang layar 
# 1. Menginisialisasi folder menjadi repositori Git
git init -b main

# 2. Mengatur identitas pembuat commit
git config user.name "Nama Anda"
git config user.email "email@anda.com"

# 3. Membuat file .gitignore untuk menyaring file rahasia & sampah
echo "node_modules/
.env
.env.local
.DS_Store
dist/" > .gitignore
02

Modul 2: Pemeriksaan Status (git status) & Pendaftaran Antrean (git add)

Melihat apa saja yang berubah di proyek dan memilih file yang layak dimasukkan ke antrean staging

Perintah Terkait: git status git add <file> git add . Konsep: Staging Area

Sebelum mengambil foto simpanan (commit), Anda perlu melihat file mana saja yang baru dibuat, diedit, atau dihapus, lalu memasukkannya ke antrean Staging Area.

PROMPT 2 — AUDIT STATUS & STAGING PERUBAHAN 
Tolong periksa kondisi berkas pada proyek saya saat ini menggunakan 'git status'.

Bantu saya dengan urutan berikut:
1. Rangkumkan file apa saja yang baru dibuat (untracked), file apa yang dimodifikasi (modified), dan apakah ada file yang dihapus.
2. Pastikan tidak ada file rahasia (.env atau credential) yang tidak sengaja terbaca.
3. Masukkan seluruh file yang relevan ke dalam Staging Area ('git add .').
4. Konfirmasikan kepada saya daftar berkas yang sudah berhasil berada di zona Staging Area dan siap untuk di-commit.
🔍 Klik untuk melihat perintah Terminal (CLI) yang dijalankan AI di belakang layar 
# Memeriksa status file (merah = belum staged, hijau = sudah staged)
git status -s

# Memasukkan file spesifik atau seluruh folder ke antrean staging
git add index.html app.js
git add .
03

Modul 3: Snapshot Simpanan Permanen (git commit) Standar Industri

Membekukan versi kode dengan pesan commit deskriptif mengikuti standar Conventional Commits

Perintah Terkait: git commit -m Best Practice: Conventional Commits (feat, fix, docs, refactor)

Commit adalah titik simpan permanen. Sebagai pengembang profesional, pesan commit tidak boleh hanya "update", melainkan harus menjelaskan konteks perubahan secara jelas.

PROMPT 3 — COMMIT DENGAN CONVENTIONAL COMMITS 
Tolong analisis seluruh perubahan berkas yang saat ini ada di Staging Area.

Bantu saya membuatkan Commit resmi dengan kriteria berikut:
1. Buat pesan commit yang profesional dan deskriptif mengikuti kaidah Conventional Commits (misalnya berawalan 'feat:', 'fix:', 'docs:', 'style:', atau 'refactor:').
2. Berikan rincian ringkas poin-poin fitur atau perbaikan yang dikandung dalam commit ini.
3. Eksekusi perintah 'git commit -m "..."' tersebut.
4. Tampilkan hash commit (ID unik) dan bukti bahwa commit telah tersimpan rapi di repositori lokal.
🔍 Klik untuk melihat perintah Terminal (CLI) yang dijalankan AI di belakang layar 
# Mengambil snapshot dengan pesan commit standar
git commit -m "feat: integrasi auth supabase dan validasi input form"

# Memeriksa daftar snapshot riwayat yang tersimpan
git log --oneline -n 5
04

Modul 4: Mesin Waktu & Pemulihan Kode (git restore, unstage, revert)

Membatalkan perubahan error, membuang kode rusak buatan AI, atau mengembalikan snapshot masa lalu

Perintah Terkait: git restore <file> git restore --staged <file> git revert Penyelamat: Anti-Rusak
⚠️ Peringatan Dosen: git restore . akan menghapus perubahan yang belum di-commit dan mengembalikannya persis seperti saat commit terakhir. Gunakan prompt ini jika AI merusak logika kode Anda dan Anda ingin kembali ke kondisi aman sebelumnya.
PROMPT 4A — MEMBATALKAN PERUBAHAN ERROR (DISCARD / RESTORE) 
Halo Antigravity, kode yang baru saja kita ubah mengalami error dan tampilannya berantakan.

Saya ingin memulihkan keadaan proyek ke kondisi bersih saat commit terakhir:
1. Jika ada file yang terlanjur dimasukkan ke staging area ('staged'), tolong keluarkan kembali menggunakan 'git restore --staged .'.
2. Buang seluruh modifikasi yang belum di-commit pada file yang rusak menggunakan 'git restore .' agar file kembali utuh seperti semula.
3. Hapus file-file baru yang tidak diinginkan/sampah menggunakan 'git clean -fd' jika ada.
4. Pastikan status git kembali bersih (clean working tree) dan laporkan hasilnya.
PROMPT 4B — ROLLBACK SNAPSHOT LAMA TANPA MERUSAK RIWAYAT (REVERT) 
Saya ingin membatalkan fitur tertentu yang sudah terlanjur di-commit sebelumnya.

Tolong bantu saya:
1. Periksa 5 riwayat commit terakhir menggunakan 'git log --oneline'.
2. Tunjukkan kepada saya daftar commit tersebut beserta ringkasan fungsinya.
3. Batalkan perubahan dari commit yang salah tersebut secara aman menggunakan 'git revert <COMMIT_HASH>' (tanpa menghapus riwayat masa lalu).
4. Pastikan aplikasi dapat berjalan kembali normal.
🔍 Klik untuk melihat perintah Terminal (CLI) yang dijalankan AI di belakang layar 
# 1. Membatalkan status staged (mengeluarkan file dari antrean commit)
git restore --staged index.html
git restore --staged .

# 2. Membuang perubahan uncommitted (mengembalikan file ke titik commit terakhir)
git restore index.html
git restore .

# 3. Menghapus file baru yang belum terlacak (untracked files)
git clean -fd

# 4. Membatalkan commit tertentu secara elegan dengan membuat commit pembalik
git revert a1b2c3d
05

Modul 5: Dokumentasi Portofolio Proyek (README.md Standar Industri)

Mempersiapkan halaman etalase GitHub dengan visualisasi badge, arsitektur, dan panduan instalasi

Dokumentasi: README.md Portofolio & Showcasing

Repositori GitHub tanpa README.md bagaikan etalase toko tanpa plang nama. Gunakan prompt ini agar AI menyusun file dokumentasi yang siap memukau calon klien atau recruiter.

PROMPT 5 — GENERATOR README.MD PROFESIONAL 
Tolong buatkan file README.md yang komprehensif, menarik secara visual, dan berstandar profesional untuk proyek ini.

Pastikan memuat komponen-komponen berikut:
1. 🏷️ Judul proyek & satu kalimat elevator pitch yang memikat.
2. ✨ Fitur-fitur unggulan (Key Features) dalam format bullet list berikon.
3. 🛠️ Tech Stack & Dependensi yang digunakan (HTML5, CSS3, JS/React/Next.js/Supabase dll).
4. 🚀 Panduan Instalasi & Menjalankan Proyek di komputer lokal (Local Setup).
5. 📂 Struktur Folder Proyek secara ringkas.
6. 🛡️ Variabel Environment (.env.example) jika ada yang dibutuhkan.
7. 👤 Lisensi dan Nama Pembuat (Author).

Tulis dalam format Markdown GitHub yang rapi dengan heading hierarkis.
🔍 Klik untuk melihat perintah Terminal (CLI) yang dijalankan AI di belakang layar 
# Memeriksa apakah README.md sudah ada atau perlu di-stage
git add README.md
git commit -m "docs: perbarui dokumentasi README.md dan panduan instalasi"

Modul 6: Menghubungkan ke GitHub Remote & First Push (Upload Perdana)

Mendaftarkan remote origin ke cloud GitHub, menetapkan branch main, dan mengunggah repositori

Perintah Terkait: git remote add origin <url> git branch -M main git push -u origin main
📌 Langkah Persiapan di Browser (Hanya 1 Menit):
1. Buka github.com/new di tab browser.
2. Masukkan Repository name (contoh: aplikasi-kasir-vibe).
3. Pilih Public. Biarkan pilihan README / .gitignore KOSONG (Jangan dicentang).
4. Klik tombol hijau Create repository, lalu salin URL HTTPS (contoh: https://github.com/username/repo.git).
PROMPT 6 — HUBUNGKAN & PUSH PERDANA 
Saya sudah membuat repository kosong di GitHub dengan URL:
[GANTI DENGAN URL GITHUB ANDA, contoh: https://github.com/username/nama-proyek.git]

Tolong hubungkan proyek lokal ini ke GitHub dan lakukan push pertama kali:
1. Pastikan seluruh file saat ini sudah ter-stage dan ter-commit dengan pesan yang rapi.
2. Ubah/pastikan nama branch utama adalah 'main' ('git branch -M main').
3. Daftarkan URL GitHub tersebut sebagai remote origin ('git remote add origin ...'). Jika remote origin sudah ada sebelumnya, tolong perbarui URL-nya.
4. Lakukan push perdana dengan pelacakan upstream ('git push -u origin main').
5. Konfirmasikan jika proses upload ke GitHub telah berhasil 100%.
🔍 Klik untuk melihat perintah Terminal (CLI) yang dijalankan AI di belakang layar 
# 1. Menamai branch utama menjadi 'main'
git branch -M main

# 2. Mendaftarkan remote origin ke cloud GitHub
git remote add origin https://github.com/username/nama-proyek.git

# 3. Mengunggah seluruh snapshot ke branch main di GitHub
git push -u origin main

Modul 7: Alur Rutin Harian 1-Prompt (Add + Commit + Push Otomatis)

Prompt instan yang Anda gunakan setiap kali selesai mengedit atau menambah fitur baru

Alur: Stage → Commit → Push Penggunaan: Harian / Setiap Sesi Selesai

Setelah repositori terhubung, di hari-hari berikutnya Anda tidak perlu lagi mendaftarkan remote. Cukup kirimkan prompt efisien ini di akhir sesi koding Anda bersama AI:

PROMPT 7 — PUSH UPDATE HARIAN SATU-LANGKAH 
Saya telah selesai memperbarui kode dan fitur pada sesi kali ini.

Tolong lakukan siklus penyimpanan penuh dan kirim ke GitHub:
1. Periksa berkas apa saja yang berubah.
2. Tambahkan semua perubahan ke staging ('git add .').
3. Buatkan commit baru dengan pesan yang ringkas dan menjelaskan fitur yang baru kita buat.
4. Lakukan 'git push' ke remote GitHub.
5. Beri tahu saya jika update online sudah live di repositori GitHub.
🔍 Klik untuk melihat perintah Terminal (CLI) yang dijalankan AI di belakang layar 
# Alur kerja 3 langkah klasik yang dieksekusi AI
git add .
git commit -m "feat: penyempurnaan UI dashboard dan perbaikan bug"
git push
08

Modul 8: Sinkronisasi Tim & Resolusi Konflik (git pull, fetch & merge)

Menarik pembaharuan kode terbaru dari cloud dan mengatasi benturan kode antar rekan tim

Perintah Terkait: git pull origin main git fetch Penanganan: Merge Conflict

Jika Anda mengedit kode dari laptop lain atau berkolaborasi dalam tim, gunakan prompt ini untuk menyinkronkan perubahan terbaru ke laptop Anda saat ini:

PROMPT 8 — SINKRONISASI PULL & RESOLUSI KONFLIK 
Tolong sinkronkan proyek lokal saya dengan pembaruan terbaru yang ada di GitHub:

1. Ambil pembaruan terbaru menggunakan 'git pull origin main'.
2. Jika ada perubahan baru dari GitHub, gabungkan ke file lokal saya.
3. JIKA terjadi benturan file (Merge Conflict), tolong jelaskan baris mana yang bertabrakan, lalu bantu pilihkan kode yang paling mutakhir dan benar agar tidak ada fitur yang hilang.
4. Selesaikan proses merge dan laporkan status proyek saat ini.
🔍 Klik untuk melihat perintah Terminal (CLI) yang dijalankan AI di belakang layar 
# Menarik kode terbaru dari server GitHub ke laptop
git pull origin main

# Memeriksa status bila ada konflik pada baris kode
git status
# Setelah konflik diperbaiki:
git add .
git commit -m "merge: menyelesaikan konflik sinkronisasi branch main"

Modul 9: Dokter Masalah Push (Troubleshooting, Rejected & Autentikasi)

Solusi otomatis saat push ditolak (non-fast-forward, remote rejected, atau otentikasi token)

Kasus Error: Updates were rejected (non-fast-forward) Permission denied (publickey) Detached HEAD
🩺 Jangan Panik Jika Terminal Merah: Kesalahan umum seperti lupa pull, repository remote berisi README bawaan yang bentrok, atau URL salah ketik dapat diselesaikan AI secara otomatis.
PROMPT 9 — DIAGNOSIS & PERBAIKAN ERROR PUSH OTOMATIS 
Proses git push saya mengalami kegagalan / muncul pesan error merah di terminal.

Tolong bertindak sebagai Senior DevOps Engineer dan perbaiki masalah ini:
1. Diagnosis penyebab error dengan menjalankan 'git status', 'git remote -v', dan 'git log -n 3'.
2. Jelaskan kepada saya dalam 1-2 kalimat apa penyebab gagalnya dengan bahasa awam yang sangat mudah dimengerti.
3. Jalankan solusi perbaikannya (misalnya melakukan 'git pull --rebase origin main' jika remote mendahului lokal, atau memperbaiki URL remote jika salah konfigurasi).
4. Lakukan push ulang hingga repositori berhasil sinkron dan hijau 100%.
🔍 Klik untuk melihat perintah Terminal (CLI) yang dijalankan AI di belakang layar 
# 1. Mengatasi error 'Updates were rejected because the remote contains work...'
git pull --rebase origin main
git push origin main

# 2. Mengubah alamat remote jika sebelumnya salah URL atau username
git remote set-url origin https://github.com/username-benar/repo.git

# 3. Memaksa push hanya jika Anda 100% yakin ingin menimpa (Gunakan dengan bijak)
git push origin main --force-with-lease

Rubrik Kelulusan Praktikum Git & GitHub

Buka repositori GitHub Anda di browser (tekan F5). Evaluasi mandiri checklist berikut:

✅ Indikator Keberhasilan Repositori:

  • Semua folder & berkas proyek muncul lengkap di GitHub.
  • Halaman README.md tampil rapi dan informatif di beranda repo.
  • Riwayat commit menunjukkan pesan deskriptif (bukan sekadar "update").
  • Branch utama resmi bernama main.

🛡️ Audit Keamanan & Integritas:

  • File .env / .env.local TIDAK ADA di daftar berkas publik GitHub (aman).
  • Folder node_modules/ berukuran raksasa tidak ikut ter-upload.
  • Tidak ada error / uncommitted changes saat mengetik git status.
