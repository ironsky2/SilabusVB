STANDAR WAJIB SEBELUM PUSH: CONVENTIONAL COMMITS
🏷️

Standar Pesan Commit Profesional (Conventional Commits)

Wajib dipatuhi sebelum mengeksekusi push agar riwayat repositori terbaca rapi oleh tim, klien, & recruiter

💡 Analogi 12 Tahun: Seperti memberi judul label kardus pindahan rumah: jangan tulis "barang" (terlalu ambigu), tapi tulis "dapur: piring keramik & sendok" agar semua orang tahu persis isinya tanpa harus membuka kardusnya!

Format standar industri memiliki struktur: <tipe>: <deskripsi ringkas dalam kalimat aktif>

✨ feat: (Fitur Baru)
Menambahkan fitur atau komponen baru ke aplikasi.
feat: tambah validasi form registrasi
🐛 fix: (Perbaikan Bug)
Memperbaiki bug atau kesalahan fungsi pada kode.
fix: perbaiki tombol hitung total harga
📝 docs: (Dokumentasi)
Perubahan pada file dokumentasi seperti README.md.
docs: perbarui panduan instalasi lokal
🎨 style: (Tampilan/Styling)
Perubahan CSS, tata letak, atau format tanpa ubah logika.
style: perbaiki warna navbar mode gelap
♻️ refactor: (Struktur Kode)
Merapikan struktur kode tanpa mengubah fungsi luarnya.
refactor: pisahkan fungsi kalkulasi ke helper
🤖 PROMPT AI: GENERATOR CONVENTIONAL COMMITS OTOMATIS
"Tolong periksa seluruh file di Staging Area saat ini. Analisis perubahannya dan buatkan pesan commit profesional berformat Conventional Commits yang ringkas dan deskriptif (misal 'feat: ...' atau 'fix: ...'). Setelah itu, jalankan git commit dan tampilkan hasilnya."
7 MODUL PRAKTIKUM GITHUB CLOUD

Modul 1: Dokumentasi Portofolio Proyek (README.md Standar Industri)

Mempersiapkan etalase GitHub dengan visualisasi badge, arsitektur, panduan instalasi, dan tech stack

Dokumentasi: README.md Portofolio & Showcasing
💡 Analogi 12 Tahun: Repositori tanpa README.md bagaikan etalase toko tanpa plang nama dan buku menu. Pembeli (recruiter/klien) akan bingung apa fungsi toko Anda!
Commit File README.md
git add README.md && git commit -m "docs: ..."
Menyimpan snapshot dokumentasi resmi ke repositori lokal sebelum di-push.
🤖 PROMPT AI KE ASISTEN IDE
"Tolong buatkan file README.md yang komprehensif, menarik secara visual, dan berstandar profesional untuk proyek ini dalam Bahasa Indonesia. Jelaskan tujuan proyek, fitur-fitur utama, teknologi yang dipakai, struktur folder, dan panduan cara menjalankannya."
02

Modul 2: Menghubungkan ke GitHub Remote & Menetapkan Branch Main

Mendaftarkan URL tujuan di GitHub Cloud dan menyelaraskan nama branch utama lokal

Perintah: git remote add origin git branch -M main git remote -v
💡 Analogi 12 Tahun: Mendaftarkan alamat pos brankas awan di internet (GitHub Cloud) ke dalam buku telepon laptopmu dengan nama panggilan origin.
📌 Langkah Persiapan di Browser (Hanya 1 Menit):
1. Buka github.com/new di browser.
2. Masukkan Repository name (contoh: aplikasi-kasir-vibe).
3. Pilih Public. Biarkan pilihan README & .gitignore KOSONG (Jangan dicentang).
4. Klik tombol hijau Create repository, lalu salin URL HTTPS (contoh: https://github.com/username/repo.git).
1. Hubungkan ke GitHub
git remote add origin https://github.com/<USER>/<REPO>.git
Mendaftarkan tautan repo GitHub sebagai tujuan pengiriman bernama origin.
2. Tetapkan Branch Main
git branch -M main
Memastikan nama branch utama lokal selaras dengan standar GitHub modern (main).
3. Cek Status Koneksi Remote
git remote -v
Memastikan alamat fetch dan push sudah terhubung dengan benar ke GitHub.
🤖 PROMPT AI KE ASISTEN IDE
"Saya sudah membuat repo kosong di GitHub dengan link https://github.com/USERNAME/REPO.git. Tolong ubah branch utama menjadi 'main' dan daftarkan link tersebut sebagai remote origin."
03

Modul 3: Unggah Perdana ke GitHub (First Push Upstream)

Mengirim seluruh riwayat snapshot lokal ke GitHub dan mengaktifkan pelacakan otomatis (-u)

Perintah: git push -u origin main Koneksi Awan
💡 Analogi 12 Tahun: Mengirim truk kargo pertama yang memindahkan salinan seluruh album foto dari memori laptopmu ke brankas awan GitHub agar bisa dilihat oleh seluruh dunia.
Unggah Perdana (First Push)
git push -u origin main
Mengunggah seluruh commit dan mengunci pelacakan upstream antara branch main lokal dan remote.
🤖 PROMPT AI KE ASISTEN IDE
"Tolong lakukan first push ke branch main di GitHub dengan 'git push -u origin main'. Konfirmasikan kepada saya jika proses upload sudah berhasil 100%."
04

Modul 4: Alur Push Rutin Harian (Daily Push Workflow)

Siklus 1-langkah efisien setiap kali Anda selesai menambah fitur atau mengedit kode bersama AI

Alur: Stage → Commit → Push Harian / Sesi Selesai
💡 Analogi 12 Tahun: Setelah kargo pertama terhubung di Modul 3, di hari-hari selanjutnya kamu cukup menekan 1 tombol git push saja untuk mengirim update harian!
Push Rutin Harian
git push
Cukup ketik git push saja untuk pengunggahan di sesi-sesi selanjutnya!
🤖 PROMPT AI KE ASISTEN IDE
"Saya telah selesai memperbarui fitur ini. Tolong stage semua file, buatkan commit berformat Conventional Commits yang deskriptif, dan lakukan 'git push' ke GitHub."
05

Modul 5: Sinkronisasi Tim & Resolusi Konflik (git pull & merge)

Menarik pembaharuan kode terbaru dari cloud GitHub dan mengatasi benturan kode antar rekan tim

Perintah: git pull origin main git fetch Solusi: Merge Conflict
💡 Analogi 12 Tahun: Mengunduh lembar jawaban terbaru dari teman sekelompok di awan. Jika ada baris tulisan yang bertabrakan di halaman yang sama, kita diskusikan mana versi yang paling benar!
Tarik Update dari GitHub
git pull origin main
Mengunduh pembaruan terbaru di GitHub dan menggabungkannya ke repo lokal.
Cek Status Konflik
git status
Mendeteksi file mana saja yang mengalami both modified (konflik baris kode).
🤖 PROMPT AI KE ASISTEN IDE
"Tolong sinkronkan proyek lokal saya dengan 'git pull origin main'. Jika terjadi Merge Conflict (benturan baris kode), tolong jelaskan letak konfliknya dan bantu selesaikan secara aman agar tidak ada fitur yang hilang."
06

Modul 6: Dokter Masalah Push (Troubleshooting & Perbaikan Error)

Solusi otomatis saat push ditolak (non-fast-forward, remote rejected, salah URL, atau otentikasi)

Updates were rejected (non-fast-forward) Permission denied (token/auth) Remote URL Mismatch
🩺 Jangan Panik Jika Terminal Merah: Kesalahan umum seperti lupa pull, repository remote berisi README bawaan yang bentrok, atau salah ketik URL GitHub dapat diperbaiki otomatis.
Atasi Push Ditolak (Rebase)
git pull --rebase origin main
Menyelaraskan commit lokal di atas commit terbaru server GitHub sebelum push ulang.
Perbaiki URL Remote
git remote set-url origin <URL_BARU>
Mengubah alamat URL GitHub jika sebelumnya terjadi saltik (typo) atau ganti akun.
🤖 PROMPT AI KE ASISTEN IDE
"Proses git push saya mengalami kegagalan / muncul error merah di terminal. Tolong diagnosis penyebab error dengan 'git status', 'git remote -v', dan 'git log -n 3', jelaskan penyebabnya secara sederhana, lalu jalankan solusinya hingga sukses push 100%."

Modul 7: Koleksi Super Prompt AI untuk GitHub & Cloud

Prompt pilihan paling sering dipakai untuk audit keamanan, generator README, dan otomasi sinkronisasi cloud

🔥 Prompt 1: Audit Keamanan Sebelum Push
"Tolong periksa seluruh file di proyek ini sebelum saya push ke GitHub. Pastikan tidak ada API Key, password, token rahasia, atau file konfigurasi .env yang belum masuk ke .gitignore."
🔥 Prompt 2: Pembuatan Dokumentasi README.md Portofolio
"Tolong buatkan file README.md yang menarik dan profesional untuk proyek ini dalam Bahasa Indonesia. Jelaskan tujuan proyek, fitur-fitur utama, teknologi yang dipakai, dan panduan cara menjalankannya."
🔥 Prompt 3: Alur Push Rutin 1-Langkah
"Saya telah selesai memperbarui fitur ini. Tolong stage semua file, buatkan commit berformat Conventional Commits yang deskriptif, dan lakukan 'git push' ke GitHub."

Rubrik Kelulusan Praktikum Pertemuan 6 (GitHub Cloud)

Buka repositori GitHub Anda di browser (tekan F5). Evaluasi mandiri checklist berikut:

✅ Indikator Keberhasilan Repositori:

  • Semua berkas proyek muncul lengkap di GitHub.
  • Halaman README.md tampil rapi dan informatif di beranda repo.
  • Riwayat commit berformat Conventional Commits (misal: feat:, fix:, docs:).
  • Branch utama resmi bernama main.

🛡️ Audit Keamanan & Integritas:

  • File .env / .env.local TIDAK ADA di GitHub (terlindungi .gitignore).
  • Folder node_modules/ berukuran raksasa tidak ikut ter-upload.
  • Status lokal bersih (clean working tree) saat mengetik git status.
