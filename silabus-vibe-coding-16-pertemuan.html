6

Modul 6: Push Project ke GitHub — Backup & Kolaborasi Cloud

Bangun Halaman Pertama 90 menit Modul Praktikum Lengkap

Tujuan: Proyek tersimpan aman di cloud GitHub — bisa diakses dari mana saja, punya riwayat commit lengkap, terproteksi dari kebocoran kredensial (anti-leak), dan siap untuk auto-deploy hosting Netlify/Vercel.

📚 Teori

  • GitHub = "lemari brankas online" — repo di laptop bukan cadangan yang aman jika laptop rusak atau hilang
  • Kamus istilah sederhana: Repository = Gudang proyek, Commit = Catatan simpanan, Push = Upload ke cloud, .gitignore = Daftar barang terlarang
  • Mengapa Vibe Coder tidak perlu menghafal perintah terminal — cukup pahami konsepnya, biarkan AI yang menjalankannya
  • Cara mengamankan file rahasia: .env.local dan node_modules/ wajib masuk .gitignore sebelum push
  • Menulis README.md profesional melalui prompt AI agar proyek bisa dipahami orang lain

🧑‍💻 Praktikum — 5 Prompt AI

💡 Buka halaman materi lengkap untuk menyalin 5 prompt siap pakai ini.

  • Prompt 1: Minta AI buatkan .gitignore lengkap & aman anti-bocor kredensial
  • Prompt 2: Minta AI tulis README.md profesional dari deskripsi proyek
  • Prompt 3: Hubungkan & push ke GitHub pertama kali (cukup berikan URL repo)
  • Prompt 4: Simpan & upload perubahan terbaru (prompt harian singkat)
  • Prompt 5: Penyelamat jika push gagal — AI diagnosa & perbaiki otomatis
🚀

Materi Lengkap Modul 6: Panduan Praktikum Push ke GitHub

Di halaman ini Anda akan mendapatkan: Teori konsep GitHub (analogi brankas, kamus 4 istilah inti) + 5 prompt AI siap salin untuk membuat .gitignore, menulis README.md, melakukan push pertama kali, menyimpan perubahan harian, dan menyelamatkan diri jika push gagal — tanpa perlu mengetik satu perintah terminal pun!

📘 Buka Halaman Materi Lengkap: panduan_push_github.html →
!

Cek sebelum push: Jalankan git status dan pastikan tidak ada file yang mengandung password, API key, atau kredensial rahasia yang ikut masuk ke dalam commit. Sekali ter-push ke repo publik, kunci harus segera di-revoke.

Output pertemuan Repo GitHub live dengan README.md terisi, .gitignore aman, dan seluruh commit riwayat proyek terlihat.
Kesalahan yang sering terjadi Lupa menambahkan .env.local ke .gitignore sebelum push — API key bocor ke publik dan harus di-rotate ulang.

Menulis Skema SQL & DDL di Supabase

DDL Tables · Foreign Key Cascade · Triggers · Index Performa

Konsep: DDL (Data Definition Language) adalah perintah SQL untuk mendefinisikan kerangka struktur database. Kita membuat tabel profiles, categories, dan transactions dengan trigger otomatis pembuatan profil saat user sign-up.

PROMPT KE ANTIGRAVITY AGENT 
[ROLE]: Supabase Database Architect & PostgreSQL Security Specialist
[CONTEXT]: Stack: Vite + React 18 (TypeScript) + @supabase/supabase-js. Aplikasi manajemen keuangan pribadi multi-user.
[INSTRUCTION]:
Buatkan script SQL DDL lengkap untuk Supabase dengan ketentuan:
1. TABEL profiles (id UUID PK references auth.users ON DELETE CASCADE, full_name, avatar_url, updated_at).
2. TABEL categories (id UUID PK, user_id UUID references auth.users ON DELETE CASCADE, name, color, icon, created_at).
3. TABEL transactions (id UUID PK, user_id UUID references auth.users ON DELETE CASCADE, category_id UUID references categories ON DELETE SET NULL, title, amount NUMERIC(15,2), type CHECK ('income','expense'), note, date, created_at).
4. FUNCTION & TRIGGER handle_new_user() untuk auto-create row di profiles saat user baru terdaftar di auth.users.
5. FUNCTION & TRIGGER update_updated_at_column() pada profiles.
6. INDEX performa pada transactions.user_id, transactions.date, categories.user_id.
[CONSTRAINT]:
- Siap dijalankan di Supabase SQL Editor.
- Tanpa RLS dahulu (RLS akan dibuat terpisah).
SQL OUTPUT — Eksekusi di Supabase Dashboard → SQL Editor 
-- 1. FUNCTION: Auto-update timestamp saat row dimodifikasi
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 2. TABEL PROFILES (relasi 1-to-1 dengan auth.users)
CREATE TABLE IF NOT EXISTS public.profiles (
  id          UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY,
  full_name   TEXT,
  avatar_url  TEXT,
  updated_at  TIMESTAMPTZ DEFAULT now()
);

CREATE OR REPLACE TRIGGER profiles_updated_at
  BEFORE UPDATE ON public.profiles
  FOR EACH ROW EXECUTE FUNCTION update_updated_at_column();

-- 3. TABEL CATEGORIES (per user)
CREATE TABLE IF NOT EXISTS public.categories (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  color       TEXT DEFAULT '#028090',
  icon        TEXT DEFAULT 'tag',
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 4. TABEL TRANSACTIONS (catatan keuangan)
CREATE TABLE IF NOT EXISTS public.transactions (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  category_id UUID REFERENCES public.categories(id) ON DELETE SET NULL,
  title       TEXT NOT NULL,
  amount      NUMERIC(15,2) NOT NULL,
  type        TEXT NOT NULL CHECK (type IN ('income', 'expense')),
  note        TEXT,
  date        DATE DEFAULT CURRENT_DATE,
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 5. FUNCTION + TRIGGER: Auto-buat profile saat user baru terdaftar
CREATE OR REPLACE FUNCTION handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.profiles (id, full_name, avatar_url)
  VALUES (
    NEW.id,
    NEW.raw_user_meta_data ->> 'full_name',
    NEW.raw_user_meta_data ->> 'avatar_url'
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE OR REPLACE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION handle_new_user();

-- 6. INDEX PERFORMA
CREATE INDEX IF NOT EXISTS idx_transactions_user_id ON public.transactions(user_id);
CREATE INDEX IF NOT EXISTS idx_transactions_date     ON public.transactions(date DESC);
CREATE INDEX IF NOT EXISTS idx_categories_user_id    ON public.categories(user_id);
02

Row Level Security (RLS) Policies & Visual Komparasi

Firewall Database per Baris · Isolasi Multi-Tenant · Keamanan Mutlak

Memahami RLS: Tanpa RLS aktif, query SELECT * FROM transactions akan mengembalikan seluruh baris data semua user. Dengan RLS aktif, engine PostgreSQL menyisipkan filter WHERE user_id = auth.uid() secara otomatis di level database.

🔴 TANPA RLS (Data Bocor!)
SELECT * FROM transactions;

PostgreSQL mengeksekusi tanpa filter kepemilikan. Hasil:

user_idtitleamount
user-A (kamu)Gaji Bulanan5.000.000
user-B (orang lain!)Bonus Tahunan20.000.000
user-C (orang lain!)Beli Saham15.000.000

⚠️ User A bisa melihat seluruh transaksi User B & C!

🟢 DENGAN RLS (Aman & Terisolasi)
SELECT * FROM transactions;
+ PostgreSQL otomatis menambahkan WHERE user_id = auth.uid()
user_idtitleamount
user-A (kamu)Gaji Bulanan5.000.000
user-BBonus Tahunan20.000.000
user-CBeli Saham15.000.000

✅ Hanya baris milik user yang sedang login yang dikirimkan.

SQL RLS POLICIES — Eksekusi di Supabase SQL Editor 
-- 1. PROFILES POLICIES
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;

CREATE POLICY "profiles: select own"
  ON public.profiles FOR SELECT
  USING (auth.uid() = id);

CREATE POLICY "profiles: update own"
  ON public.profiles FOR UPDATE
  USING (auth.uid() = id) WITH CHECK (auth.uid() = id);

-- 2. CATEGORIES POLICIES
ALTER TABLE public.categories ENABLE ROW LEVEL SECURITY;

CREATE POLICY "categories: select own" ON public.categories FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY "categories: insert own" ON public.categories FOR INSERT WITH CHECK (auth.uid() = user_id);
CREATE POLICY "categories: update own" ON public.categories FOR UPDATE USING (auth.uid() = user_id);
CREATE POLICY "categories: delete own" ON public.categories FOR DELETE USING (auth.uid() = user_id);

-- 3. TRANSACTIONS POLICIES
ALTER TABLE public.transactions ENABLE ROW LEVEL SECURITY;

CREATE POLICY "transactions: select own" ON public.transactions FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY "transactions: insert own" ON public.transactions FOR INSERT WITH CHECK (auth.uid() = user_id);
CREATE POLICY "transactions: update own" ON public.transactions FOR UPDATE USING (auth.uid() = user_id);
CREATE POLICY "transactions: delete own" ON public.transactions FOR DELETE USING (auth.uid() = user_id);

AuthContext, Custom Hook `useAuth` & Route Guard

React Context · onAuthStateChange · Session Cleanup · ProtectedRoute

Sistem autentikasi multi-halaman dengan session tracking reaktif dan proteksi rute halaman privat:

FILE: src/context/AuthContext.tsx 
import { createContext, useContext, useEffect, useState, useCallback } from 'react';
import type { ReactNode } from 'react';
import type { Session, User, AuthError } from '@supabase/supabase-js';
import { supabase } from '../lib/supabase';
import type { Profile } from '../types/database.types';

interface AuthContextType {
  user: User | null;
  session: Session | null;
  profile: Profile | null;
  loading: boolean;
  signUpWithEmail: (e: string, p: string, name: string) => Promise<{ error: AuthError | null }>;
  signInWithEmail: (e: string, p: string) => Promise<{ error: AuthError | null }>;
  signOut: () => Promise<void>;
}

const AuthContext = createContext<AuthContextType | undefined>(undefined);

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const [session, setSession] = useState<Session | null>(null);
  const [profile, setProfile] = useState<Profile | null>(null);
  const [loading, setLoading] = useState<boolean>(true);

  const fetchProfile = useCallback(async (userId: string) => {
    const { data } = await supabase.from('profiles').select('*').eq('id', userId).single();
    setProfile(data);
  }, []);

  useEffect(() => {
    supabase.auth.getSession().then(({ data: { session } }) => {
      setSession(session);
      setUser(session?.user ?? null);
      if (session?.user) fetchProfile(session.user.id);
      setLoading(false);
    });

    const { data: { subscription } } = supabase.auth.onAuthStateChange((_evt, session) => {
      setSession(session);
      setUser(session?.user ?? null);
      if (session?.user) fetchProfile(session.user.id);
      else setProfile(null);
      setLoading(false);
    });

    return () => subscription.unsubscribe(); // Safe Cleanup
  }, [fetchProfile]);

  const signUpWithEmail = async (email: string, password: string, fullName: string) => {
    const { error } = await supabase.auth.signUp({
      email, password, options: { data: { full_name: fullName } }
    });
    return { error };
  };

  const signInWithEmail = async (email: string, password: string) => {
    const { error } = await supabase.auth.signInWithPassword({ email, password });
    return { error };
  };

  const signOut = async () => { await supabase.auth.signOut(); };

  return (
    <AuthContext.Provider value={{ user, session, profile, loading, signUpWithEmail, signInWithEmail, signOut }}>
      {children}
    </AuthContext.Provider>
  );
}

export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) throw new Error('useAuth harus digunakan di dalam <AuthProvider>');
  return context;
}
FILE: src/components/ProtectedRoute.tsx 
import { Navigate, Outlet, useLocation } from 'react-router-dom';
import { useAuth } from '../context/AuthContext';

export function ProtectedRoute() {
  const { user, loading } = useAuth();
  const location = useLocation();

  if (loading) {
    return (
      <div style={{ minHeight: '100vh', display: 'flex', alignItems: 'center', justifyContent: 'center' }}>
        <p>Memeriksa sesi login...</p>
      </div>
    );

  if (!user) {
    return <Navigate to="/login" state={{ from: location.pathname }} replace />;
  }

  return <Outlet />;
}

Realtime Subscription Hook dengan Safe Cleanup

supabase.channel() · Auto Reconnect · Memory Leak Prevention · Optimistic Update

Custom Hook useTransactions yang otomatis menyinkronkan data antar-perangkat secara realtime dan membersihkan koneksi WebSocket saat komponen di-unmount:

FILE: src/hooks/useTransactions.ts 
import { useState, useEffect, useCallback } from 'react';
import { supabase } from '../lib/supabase';
import { useAuth } from '../context/AuthContext';
import type { Transaction, TransactionInsert } from '../types/database.types';

export function useTransactions() {
  const { user } = useAuth();
  const [transactions, setTransactions] = useState<Transaction[]>([]);
  const [isLoading, setIsLoading] = useState<boolean>(true);

  const fetchTransactions = useCallback(async () => {
    if (!user) { setTransactions([]); setIsLoading(false); return; }
    setIsLoading(true);
    const { data } = await supabase
      .from('transactions')
      .select('*, categories(*)')
      .eq('user_id', user.id)
      .order('date', { ascending: false });
    setTransactions((data as Transaction[]) ?? []);
    setIsLoading(false);
  }, [user]);

  useEffect(() => {
    fetchTransactions();
    if (!user) return;

    // Realtime channel filter user_id
    const channel = supabase
      .channel(`transactions_${user.id}`)
      .on(
        'postgres_changes',
        { event: '*', schema: 'public', table: 'transactions', filter: `user_id=eq.${user.id}` },
        () => { fetchTransactions(); }
      )
      .subscribe();

    // Cleanup: cegah memory leak saat unmount
    return () => { supabase.removeChannel(channel); };
  }, [user, fetchTransactions]);

  const addTransaction = async (data: TransactionInsert) => {
    if (!user) return { error: 'Belum login' };
    const { error } = await supabase.from('transactions').insert({ ...data, user_id: user.id });
    return { error: error?.message ?? null };
  };

  const deleteTransaction = async (id: string) => {
    // Optimistic delete UI
    const prev = [...transactions];
    setTransactions(t => t.filter(x => x.id !== id));
    const { error } = await supabase.from('transactions').delete().eq('id', id);
    if (error) setTransactions(prev); // rollback jika gagal
    return { error: error?.message ?? null };
  };

  return { transactions, isLoading, addTransaction, deleteTransaction, refetch: fetchTransactions };
}
